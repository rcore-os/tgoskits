# StarryOS 系统调用兼容性

## 1. 适用范围

是否触发本技能按用户可见语义判断，不按系统调用入口文件判断。任务、虚拟文件系统、命名空间、凭据、信号、套接字、内存管理、文件描述符、进程状态和辅助代码只要改变系统调用返回值、错误码、检查顺序、状态或可观察结果，都属于本技能范围。

实现或审查前完整阅读 [Linux 语义与证据](references/linux-semantics.md)。改动涉及状态、权限、并发、复制用户内存或测试时完整阅读 [状态与测试](references/state-and-testing.md)。新增系统调用或扩大用户可见能力时同时使用 `feature-development`。

## 2. 语义目标

目标是对齐选定 Linux 版本的可观察行为，而不是只让调用成功。参数解释、检查顺序、权限、命名空间、阻塞、部分完成、错误码、状态提交和并发竞争都属于接口。

未实现行为返回明确且与 Linux 语义一致的错误。不得静默成功、伪造状态、用占位 procfs 值宣称完整支持，或在错误路径留下部分提交状态。

## 3. 完成条件

每个受影响系统调用都要有可追踪的语义记录和系统级回归。记录 Linux 版本或提交、权威源码位置、StarryOS 入口与辅助调用链、预期检查顺序、状态变化和测试。测试必须通过项目 StarryOS 测试入口真实运行，并证明错误实现失败、修复后同一用例通过。
