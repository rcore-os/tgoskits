# Linux 系统调用语义与证据

## 1. 证据层级

Linux 手册页用于确认公开参数、错误码、版本和用户可见约定；与项目对齐的 Linux 源码和提交用于确认真实检查顺序、状态和竞争语义。可移植操作系统接口、正式协议规范和上游测试套件提供其他权威约束。其他内核实现、标准 C 运行库封装、博客和示例只能提供线索。

### 1.1 固定版本

Linux 行为随版本变化时记录内核版本或提交，并给出稳定源码链接。不要引用未固定分支的当前行号作为长期证据。项目明确选择与上游不同的兼容范围时，说明差异和调用方影响。

### 1.2 追踪入口

从系统调用表或入口函数开始，沿权限、对象查找、命名空间、锁、用户内存复制和状态提交追踪到最终返回。按目标体系结构检查 `arch/*/entry/syscalls/`、`arch/*/tools/syscall*.tbl`、`asm-generic/unistd.h` 及其版本对应物，确认系统调用编号和入口选择。存在兼容系统调用时继续追踪兼容入口、32 位与 64 位结构转换、参数截断以及有符号和无符号扩展。只引用入口函数而不检查辅助函数，无法证明错误顺序和边界语义。

每项语义记录至少包含：

- 系统调用名称与编号；
- 参数、标志、结构布局和单位；
- Linux 版本、源码入口与关键辅助函数；
- StarryOS 入口、领域对象和状态所有者；
- 参数、权限、对象和状态检查顺序；
- 成功结果、错误码、部分完成和副作用；
- 对应直接回归用例及项目运行入口。

## 2. 参数与错误顺序

先后顺序本身是用户可见行为。同一请求同时具有无效参数、无权限、对象不存在、状态不允许或用户指针错误时，Linux 返回哪一个错误必须由源码调用链确定。

### 2.1 参数和标志

验证未知标志、互斥组合、保留位、零值、最大值、长度溢出、结构版本和对齐。标志只影响指定对象或命名空间，不能泄漏到共享全局默认值。

输入结构应按 Linux 定义的大小和复制规则处理。支持旧结构或可变长度结构时，说明截断、尾部零填充和未知扩展的行为。

### 2.2 错误码

使用精确 Linux 错误码，区分不支持、无效参数、权限不足、对象不存在、暂不可用、资源耗尽和错误地址。不能为方便把内部错误统一映射成 `EINVAL`、`EIO` 或成功。

内部领域错误在系统调用边界集中转换。新增错误路径检查调用方和测试是否依赖旧错误，不在多个辅助层重复转换。

## 3. 返回值与部分完成

系统调用可能返回字节数、对象标识符、旧状态、剩余时间或零。不能把所有成功折叠为零，也不能在部分完成后错误地返回完整长度。

阻塞输入输出、向量操作、批量操作和用户缓冲区复制需要确认 Linux 对短操作、中断、重启和已完成部分的优先级。发生信号或缺页时，已经提交的部分是否保留必须由上游语义决定。

## 4. 二进制布局

用户可见结构、位宽、字节序、对齐、填充、时间类型和指针宽度必须匹配目标体系结构的 Linux 二进制接口。不要直接暴露 Rust 结构体布局，除非具有明确表示方式并验证所有字段和填充。

兼容层和多体系结构入口要分别检查。测试至少覆盖一个会暴露布局差异的边界值，而不只覆盖全零结构。
