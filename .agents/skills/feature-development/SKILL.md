# 功能开发

## 1. 适用范围

新增能力、扩大既有行为、引入共享边界或改变平台与硬件支持时使用本技能。是否适用按真实行为判断，不按“修复”“重构”或“清理”等标题判断。纯粹恢复既有明确语义且不扩大接口的错误修复，使用通用代码质量与相应领域技能即可。

开始设计或审查前完整阅读 [风险与研究](references/risk-and-research.md)。确定方案、实现范围、验证和交付时完整阅读 [设计与交付](references/design-and-delivery.md)。公共接口、并发、`unsafe`、驱动、平台或系统调用语义同时读取对应专项技能；同一能力涉及多个目标架构的分层复用与特异边界时还要读取 `multi-arch-layering`。

## 2. 强制顺序

按照必要性、重复性、权威语义与既有方案、现实替代方案、整体架构与接口、实现、验证与交付的顺序推进。重大前提或架构问题未解决时，不用大量低层实现制造既成事实。

高风险功能在实现合入前必须有可独立审查的设计材料，并获得合格领域审查人的认可。审查顺序是先确认问题、替代方案和整体设计，再逐行审查实现；不能用已经完成的大量实现替代设计决策。设计材料可以位于议题、设计文档或拉取请求正文，但必须稳定、可引用，并覆盖本技能要求的所有权、兼容性、迁移、回滚、可观测性、性能和安全问题。

## 3. 完成条件

功能完成不等于代码能够编译。必须证明真实用户或调用方的问题得到解决，成功标准可观察，替代方案经过比较，边界由单一所有者维护，错误与回滚明确，测试在项目运行链路真实执行，文档与迁移同步，剩余风险可被独立审查。
