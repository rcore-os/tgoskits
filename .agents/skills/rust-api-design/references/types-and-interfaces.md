# Rust 类型与接口

## 1. 类型表达不变量

类型应阻止无效状态进入核心逻辑。地址、标识符、单位、权限、队列令牌和协议字段具有不同语义时，使用新类型、枚举、位标志或经过校验的结构，而不是裸整数、字符串和关系松散的参数。

### 1.1 构造与状态

新类型包装器优先使用 `repr(transparent)` 和常量构造函数，并明确受检构造与未受检构造的边界。解析或验证完成后返回已验证类型，避免每个调用点重复检查。

状态转换具有顺序约束时，用不同状态类型、操作枚举或只能由合法前态调用的方法表达。多个布尔字段形成组合状态时，优先改成枚举；多个布尔参数控制行为时，改成配置结构或具名入口。

### 1.2 数据与行为

配置、描述符和线协议格式可以公开数据字段，但拥有资源、锁、硬件状态或复杂不变量的类型应保持表示私有，并公开表达领域意图的方法。不要让调用方修改内部索引、队列头尾、引用计数或发布状态。

按变化原因和所拥有的不变量拆分大型对象。不可变配置、已验证描述符、可变运行时状态、队列、中断端点、能力句柄和操作系统适配器的生命周期或同步规则不同时，使用独立类型。

## 2. 能力边界

特征应是小型能力集合，不是继承层次。只暴露使用方需要的操作；可选行为使用扩展特征、适配器类型或功能开关，不持续扩大中央特征。

### 2.1 组合

优先通过控制端口、队列、后端、分配器、登记表和适配器等具名部件组合服务。静态组合使用具体字段或泛型；只有运行时确实需要异构能力或插件边界时使用特征对象。

不要强迫调用方穿透多层嵌套对象。内部部件保持私有，在拥有边界上提供小而明确的方法。转发方法只有在它保护封装、补充校验或表达领域动作时才有价值。

### 2.2 所有权

接口应明确谁创建、登记、发布、借用、取消和释放资源。跨线程、设备或客户机边界传递时，不能只依赖注释约定；使用所有权类型、能力句柄、代际标识符或资源获取即初始化守卫防止重复释放、陈旧句柄和部分发布。

返回内部引用会限制后续实现和同步策略。调用方只需快照、迭代或查询时，提供边界明确的结果；热路径避免为方便而分配完整快照。

## 3. 公共错误

错误是接口的一部分。调用方需要匹配、转换、重试或回滚时，返回类型化枚举并保留原因；不要暴露字符串或 `anyhow::Error`。

### 3.1 分层转换

领域软件包使用自己的错误类型；宿主工具在顶层转为 `anyhow` 上下文；ArceOS 或内核集成边界显式转为 `AxError`。第三方软件包的错误、连接、查询、缓冲区和运行时类型应在基础设施或适配边界转换，不能穿透领域与公共接口迫使所有调用方依赖具体实现。转换必须保留未知值的明确回退，不得假定不同软件包的同名错误类型可以隐式互换。

新增错误变体时检查所有匹配点、外部数值映射、用户可见显示和兼容策略。不能为了避免修改调用方而把新的结构化错误折叠成既有宽泛错误。

## 4. 兼容性

兼容性包括 Rust 源码、功能开关、错误匹配、配置格式、序列化布局、二进制接口和运行时行为。接口不稳定不代表可以无迁移地破坏所有工作区调用方；应在同一改动中迁移现有使用者并删除废弃双轨。

只有明确需要跨版本兼容时才提供适配层。适配层要有单一所有者、清晰停止条件和测试；不得永久保留别名、回退解析和重复登记表来掩盖未完成迁移。
