# Rust 原子操作与异步执行

## 1. 原子状态

为每个原子变量写出它承载的含义：纯计数、状态发布、所有权转移、代际标识还是唤醒合并。多个原子共同表达一个不变量时，必须说明它们之间如何保持一致；无法独立证明时使用锁或单一状态对象。

### 1.1 内存顺序

同步优先使用获取、发布或获取并发布内存顺序，并明确发布者写入的数据与观察者读取的数据。发布操作之前完成受保护数据写入，获取操作确认状态后再读取这些数据。

`Relaxed` 只用于不承担同步作用的统计计数，或已经由另一条明确同步边保护的状态。使用时说明真实同步路径；“当前体系结构不会重排”不是 Rust 内存模型证明。

顺序一致只能作为确有全局排序需求的选择，不能用来掩盖不清楚的状态机。盲目增强内存顺序可能仍无法修复丢失唤醒、复合状态撕裂或生命周期错误。

### 1.2 原子更新

比较并交换循环要处理失败时返回的新值，明确弱比较交换的重试条件，并避免无界自旋。位图和标志位更新要说明各位是否独立；清除状态不能覆盖并发发布的新状态。

计数减到零触发释放时防止下溢、重复释放和从零复活。代际计数要考虑回绕；标识符复用需要额外生命周期保证，不能只依赖有限位宽计数永不碰撞。

## 2. 异步执行

异步函数的挂起点是潜在并发边界。进入挂起前确认没有持有不可跨挂起保存的锁、关中断守卫、关抢占守卫、裸借用或要求当前处理器保持不变的状态。

### 2.1 阻塞与调度

异步执行器线程上不能直接执行无界阻塞输入输出、长时间自旋或重量级同步等待。确需阻塞时使用项目已有的阻塞执行边界，并明确取消和关闭行为。

任务派生后必须有所有者：等待完成、保留句柄、纳入任务组，或有文档说明的后台生命周期。丢弃连接句柄不能成为忽略任务失败的默认方式。

### 2.2 取消安全

每个挂起点都可能发生取消。部分写入、已取出队列项、已经登记的等待者和临时取得的能力必须在取消后保持一致或由守卫回滚。无法取消安全的操作要通过不可中断阶段或显式状态机表达。

超时包装层不能让内部任务在后台继续修改已经被调用方视为失败的对象。需要保留后台工作时，返回可观察句柄并定义最终结果归属。

## 3. 审查证据

审查原子和异步改动时至少追踪一个完整发布与观察链、一个取消或错误链，以及对象的最终释放。构造具体交错说明问题，不以“可能有竞争”作为结论。

测试应验证状态和后置条件。超时只能防止测试永久挂起，不能作为成功判据；压力测试可以补充置信度，但不能替代确定性顺序测试。
