# 跨内核驱动架构参考

创建、优化或审查 `drivers/` 下的驱动时读取本文件。

## 基本原则

核心问题是操作系统接口耦合，而不是 Rust 语言可移植性。硬件逻辑通常稳定；不同内核之间变化的是锁、任务模型、直接内存访问分配与同步、设备资源映射和中断注册。

保持下列分层：

- 驱动核心层：寄存器、访问顺序、状态机、描述符格式、队列逻辑、请求完成和事件提取。
- 能力边界层：内存映射输入输出、直接内存访问、中断事件、队列契约和唤醒边界的操作系统或驱动特征接口。
- 操作系统适配层：探测、设备资源映射、扁平设备树、高级配置与电源接口或外围部件互连总线发现、中断注册、线程或工作任务创建，以及操作系统唤醒接口。
- 运行时层：阻塞、轮询、异步任务或工作任务包装。

生产代码不要建立单体 `KernelHal`。按生命周期和语义拆分；内存映射输入输出、直接内存访问、中断、任务推进和队列通常有不同所有者与性能敏感路径。

## 项目布局

可复用硬件或知识产权核软件包按设备类型放在 `drivers/`：

```text
drivers/<device-type>/<crate-name>
drivers/<device-type>/<vendor-or-family>/<crate-name>
```

目录名应准确说明设备类型。例如新的可复用块设备可以放在 `drivers/block/<vendor>/<crate>`。现有平台适配代码可能使用 `platforms/axplat-dyn/src/drivers/blk` 等历史短名；修改该层时保持既有名称。

现有示例包括：

- `drivers/npu/rockchip-npu`
- `drivers/soc/rockchip/rockchip-pm`
- `drivers/soc/rockchip/rockchip-soc`

新增可复用软件包时：

1. 加入根工作区 `members`。
2. 其他工作区软件包需要使用时，加入根 `[workspace.dependencies]`。
3. `src/` 保持可移植，并在实际可行时支持 `#![no_std]`。
4. 操作系统特定软件包不得进入普通 `[dependencies]`。
5. 根工作区已有依赖时，成员 `Cargo.toml` 使用 `<dep>.workspace = true`，不要重复直接版本。

运行时和平台接入放在其他层：

- `platforms/axplat-dyn/src/drivers/<type>/...`：动态平台、扁平设备树和探测适配。
- `platforms/axplat-dyn/src/drivers/soc/<vendor>/...`：片上系统平台适配。
- `components/axdriver_crates/axdriver_<type>`：面向 ArceOS 的通用驱动特征与适配器。

`axplat-dyn` 中的块设备接入路径如下：

- `platforms/axplat-dyn/src/drivers/blk/<driver>.rs` 负责探测、扁平设备树和映射设置；
- 可移植生命周期通过 `rdif_block::BlockController` 暴露；
- 产生只能移动的 `rdif_block::HardwareQueue` 和装箱 `rdif_block::HardIrqHandler`；
- 通过 `submit_batch_owned()` 接收有所有权请求，通过 `commit_submissions()` 每批发布一次，再由中断激活的队列所有者调用 `drain_completions()`；
- 通过 ArceOS 驱动适配层和 `rdrive` 注册控制器；
- 有界通道、阻塞文件系统包装、任务通知、直接内存访问规划和中断注册策略留在可移植接口之上。

`rdrive` 耦合只出现在适配层或明确适配功能中。可移植驱动核心不应知道 `rdrive` 如何探测或注册设备。

## 依赖边界

使用 `dma-api` 和 `mmio-api` 作为可移植能力接口。2026 年 4 月 28 日查询到：

```toml
mmio-api = "0.2.1"
dma-api = "0.7.2"
```

修改版本前运行：

```bash
cargo search mmio-api --limit 5
cargo search dma-api --limit 5
cargo info mmio-api
cargo info dma-api
```

根工作区已包含 `dma-api`。新代码广泛采用 `mmio-api` 时，可能需要把它加入根 `[workspace.dependencies]`。

## 内存映射输入输出模式

可移植核心只接收已映射寄存器区域或类型化包装器。不得从可复用代码直接调用 `axklib::mem::iomap`、`bare_test::mem::iomap`、Linux `ioremap` 或任何目标操作系统映射接口。

在适配层使用 `mmio-api`：

- 为目标操作系统或平台实现 `mmio_api::MmioOp`。
- 探测或设置阶段调用 `mmio_api::ioremap` 或等价适配接口。
- 把 `mmio_api::Mmio`、`mmio_api::MmioRaw`、`NonNull<u8>` 或类型化寄存器包装器传入驱动核心。
- 把 `mmio_api::MmioRaw::new`、原始指针转换和映射生命周期假设留在边界内。

既有 `axplat-dyn` 适配层有 `crate::drivers::iomap` 等返回 `NonNull<u8>` 的辅助函数。新代码优先用 `mmio_api::MmioOp` 包装操作系统映射。适配仍接收 `NonNull<u8>` 的旧驱动时，可以在适配层用 `mmio-api` 映射并传入 `MmioRaw::as_nonnull_ptr()`，但必须由适配器持有 `Mmio` 或映射对象，保证生命周期。

驱动核心可通过 `mmio-api`、`tock-registers` 或符合相邻软件包风格的小型类型化包装器执行易失寄存器访问。

## 直接内存访问模式

操作系统适配层实现：

```rust
impl dma_api::DmaOp for DmaImpl { /* 平台分配与缓存操作 */ }
```

设备设置创建：

```rust
let dma = dma_api::DeviceDma::new(dma_mask, &DMA_IMPL);
```

驱动核心使用 `DeviceDma` 和 `dma-api` 抽象：

- `DArray` 或 `DBox`：一致性描述符环、命令缓冲区和固定直接内存访问数据；
- `map_single_array` 或 `SArrayPtr`：映射现有缓冲区；
- `DmaDirection::{ToDevice, FromDevice, Bidirectional}`：明确缓存同步方向；
- `DmaAddr`：设备可见总线地址。

逐条检查：地址掩码或宽度、对齐、页或布局大小、缓存刷新与失效方向、映射与解除映射或分配与释放配对、所有权转移和零复制生命周期，以及中央处理器虚拟地址与总线地址的区别。

## 中断与事件模式

可移植中断处理只回答“发生了什么”；操作系统适配层回答“接下来如何执行”。

有可变运行时状态时，使用由中断注册所有的端点：

```rust
pub trait IrqHandle {
    fn handle_irq(&mut self) -> Event;
}
```

无状态原始事件提取器可以使用 `handle_irq(&self)` 或自由函数。不能只为保留外部指针而把有状态端点设计为可克隆。

`Event` 应标识事件种类、受影响队列或执行引擎、完成状态，以及错误或恢复状态。硬中断性能敏感路径只识别来源、读取并清除必要状态寄存器、返回稳定事件，避免阻塞、长时间工作和宽锁。

操作系统适配层把事件转换为目标运行时的执行原语。网络设备没有任意选择：回调只能把匹配 `NetPollGroup` 发布给其固定处理器队列执行任务。任意唤醒器、待轮询标志、全组唤醒和远端中断继续执行都违反网络所有权契约。

### 中断回调所有权

中断处理端点只在注册回调中有意义时，把所有权写进类型：

```rust
let mut irq = parts.irq;
request_irq(irq_number, Box::new(move |ctx| {
    let event = irq.handle_irq(ctx);
    publish_event(event)
}));
```

可以使用目标内核中的装箱 `FnMut` 回调、注册令牌或有所有权闭包。关键不是分配方式，而是中断框架在完整注册生命周期内拥有处理器，并以不可重入方式调用。这样能形成单一可变访问点，不需要 `Arc<Mutex<_>>`、原始指针生命周期技巧或供无关任务调用的公共接口。

应用本模式时：

- 捕获状态会变化时，使用不可重入执行契约注册。
- 释放中断动作时，先同步正在执行的回调，再销毁捕获处理器。
- 硬中断只读取或确认状态、更新队列局部状态、发布最小事件或待处理位。
- 不捕获需要分配、休眠锁、宽轮询集合锁或文件与设备管理回调的操作系统对象；通过中断安全通知或延后工作任务衔接。
- 任务侧服务和配置方法保留在独立控制端点。两侧都触碰寄存器时，使用同一所有者处理器、本地中断排除、设备中断屏蔽或有文档说明的借用门控，避免中断重入。

此所有权模式适用于串口、块完成队列、网络收发端点、输入设备、加速器和邮箱控制器。

### 网络亲和域

网络运行时在通用端点拆分上增加严格的处理器不变量。同一物理中断连接的全部轮询组属于一个亲和域。运行时选择在线 `owner_cpu`，在注册中断前固定队列执行任务，并把该 `IrqId` 的全部动作以同一固定亲和性注册。每队列消息信号扩展中断可以形成不同亲和域。

硬中断只执行有界屏蔽、确认和快照。所有者执行任务独占接收回收与补充、发送提交与完成、直接内存访问同步、预算统计和 `rearm_and_check()`。可观察不变量为：

```text
last_irq_cpu == last_poll_cpu == owner_cpu
irq_to_poll_remote_wake == 0
```

平台无法路由中断、执行任务无法固定、共享动作亲和性冲突或设备缺少原子屏蔽与重新使能时，整个物理网络发布失败。禁止退回 `IrqAffinity::Any`、远端处理器间中断、周期队列轮询、带外回调或设备专用触发任务。

安全数字输入输出无线网络应把嵌套控制器来源移入网络硬中断端点，并把卡中断重新使能留在任务上下文。固件命令、先进先出缓冲区排空、发送推进和无线网络重新配置都是所有者处理器事务。未验证芯片变体应探测失败，不能恢复旧轮询路径。

### 统一的安全数字输入输出和 AIC8800 专门化

- 安全数字或多媒体卡控制器只公开 `sdmmc-host` 能力。唯一的 `sdmmc-protocol` 软件包负责协议状态机：`native::SdMmcCard` 处理存储卡，`sdio::SdioCard` 处理仅输入输出卡。控制器和功能驱动不得自行编码命令 5、52 或 53，不得自行解析通用卡控制寄存器、功能基本寄存器或卡信息结构，也不得自行维护功能启用、就绪或中断状态。组合卡在能力边界明确支持前必须停止并报告不支持，不得发布部分能力。
- 控制器以只能移动的 `HostParts { bus, irq, card_irq }` 交付所有权：`bus` 独占命令和数据传输，`irq` 独占宿主控制器中断端点，`card_irq` 独占卡侧中断端点。协议层可以拥有并移动这些部件，但不得复制、重新构造或从全局状态取回它们；功能驱动只能接收协议层显式移交的功能与中断能力。
- AIC8800 支持严格划分为四层：
  1. 默认不依赖标准库的 `aic8800` 软件包拥有单一设备核心；`AicDevice` 通过可变借用和显式输入推进状态，不创建任务、不休眠、不主动让出处理器、不注册中断，也不依赖固件设备树、运行时驱动接口或 ArceOS。
  2. `aic8800::rdif` 在 `rdif` 功能开关下提供可移植能力适配层，拥有直接内存访问资源、有界的单生产者单消费者请求队列、宿主机状态快照和核心事件；它不拥有工作任务、调度器或操作系统锁，也不得另建第二个适配软件包。
  3. `ax-driver` 操作系统粘合层负责固件设备树发现、内存映射输入输出、CV181x 时钟、复位、引脚复用和直接内存访问能力注册。
  4. `ax-net` 或 `axruntime` 执行层负责固定处理器轮询、截止时间、中断生命周期、通知和熵来源。
- 控制器寄存器位域使用 `tock-registers` 表达。协议线格式字段使用类型化编码器表达，不得把内存映射输入输出寄存器抽象用于协议线格式。
- 板级资源与策略必须作为固件输入解析，包括固件设备树或高级配置与电源接口中的内存映射输入输出、中断、时钟、复位、电源、引脚控制、直接内存访问地址宽度、总线频率、总线宽度和网络启动策略。可移植软件包只保留规范与芯片常量，不得写入板级物理地址或产品网络配置。
- 验证必须分层且确定：宿主机使用标准 Cargo 测试；私有单元测试放在实现末尾，集成测试只通过公共接口；ArceOS 与 QEMU 验证使用 `axtest`；真实安全数字输入输出无线网络路径必须在实体板卡上验证。

### 控制、中断和队列端点

中断驱动运行时按三类端点拆分：

```text
控制端点 -> 启动、停止、配置、服务或延后排空
中断端点 -> 硬中断确认与预分配事件发布
队列端点 -> 提交并消费队列局部完成状态
```

各端点同步责任如下：

- 控制端点由任务或工作任务上下文拥有，可通过操作系统适配层调用慢服务，也可在中断安全通知后执行延后排空。
- 中断端点由中断注册拥有，读取并清除共享或破坏性中断状态，只写预分配完成状态。
- 队列端点由运行时用户独占，或受运行时队列锁保护；它只消费队列局部许可、完成和错误，不借用中断端点。

构造函数显式返回部件：

```rust
pub struct DeviceParts<Q> {
    pub control: Arc<ControlPort>,
    pub irq: IrqHandler,
    pub queues: Q,
}
```

操作系统锁放在操作系统适配层或消费者运行时，不放在可移植驱动核心。可移植软件包只表达哪些操作需要排他访问，由操作系统选择 `SpinNoIrq`、互斥锁、异步任务、逐处理器路由或工作任务串行化。

出现下列情况说明拆分仍不完整：任务代码直接调用 `irq.handle_irq()`；中断代码取得任务上下文也会持有的队列锁；队列调用可能清除其他队列事件的原始 `poll_status()`。

### 中断与任务排他

部分驱动需要中断完成代码查看任务上下文注册或删除的状态，例如 xHCI 传输环或队列完成槽。安全协议为：

- 任务上下文先屏蔽或禁用能进入该中断路径的精确设备来源，再取得修改锁并更新登记表。
- 中断上下文不取得修改锁，只通过窄性能敏感访问器读取中断启用前已经建立生命周期的条目。
- 性能敏感访问器通过不安全接口或文档明确要求的排他与生命周期契约。
- 共享状态只含稳定描述符、队列槽、原子量或就绪位，不得在中断中要求分配、阻塞、宽操作系统锁或文件与设备管理回调。
- 任务侧完整发布新状态后才能重新启用中断源。

这能防止任务持有自旋锁时被同一设备中断，中断处理器再请求同一锁的死锁。它并不使任意唤醒器、堆分配、休眠锁或无关子系统锁在硬中断中变得安全。无法证明协议时，改用原子待处理位和操作系统适配层延后工作任务。

### 中断与队列隔离

把中断端点视为状态同步器，而不是队列所有者：

- 中断端点对象与发送、接收、完成、块请求或加速器队列完全分离。
- 中断端点是共享或破坏性状态寄存器的唯一运行时读取和清除者。队列不得重新读取同一全局寄存器。
- 通过逐队列原子量、位图、计数器或待处理列表，把中断结果分发到队列局部完成状态，并把错误与就绪分开保存。
- 硬件在一个状态寄存器中合并多个队列或方向时，中断端点立即拆分，队列代码只能看到各自状态。
- 中断到达时若另一上下文占有原始寄存器块，记录待处理中断位并快速返回；之后在安全上下文或下一次中断中排空，不在中断上下文自旋。
- 原始事件快照保持贴近硬件语义，操作系统唤醒、任务调度和队列完成所有权留在上层适配或运行时。

## 队列与运行时模式

网络发送与接收、非易失性存储管理与输入输出队列、块请求队列及加速器命令队列都应建模为独立运行单元。常见操作包括 `submit`、`reclaim`、消费同步事件状态，以及块队列的 `submit_batch_owned`、`commit_submissions` 和确认中断后的 `drain_completions`。

通用驱动可以由运行时包装为阻塞循环、事件驱动唤醒、`Future::poll` 或逐队列工作任务。网络生产运行时没有这些后备选择：它固定使用中断激活、固定处理器轮询组执行任务、有界批次和原子排空与重新使能检查，不提供纯轮询或周期工作任务模式。

硬件有多个队列或执行引擎时，避免单一全局 `Driver::poll`，也避免“大对象、大锁、回调集合”结构，除非设备确实非常简单。

中断驱动拆分设计中：

- 队列 `poll` 只回答本队列是否有已同步的完成、预算、错误或就绪状态，不读取或清除全局硬件中断状态。
- 队列 `submit` 或 `try_write` 消费自身许可或描述符预算，只编程推进该队列所需的寄存器路径。
- 队列 `reclaim` 或 `try_read` 只消费自身完成或错误，不因共享寄存器而拿走其他队列事件。
- 破坏性读取同时报告多个队列或方向时，在中断事件层立即拆分后再运行队列代码。
- 先进先出设备的一次就绪中断可覆盖有界突发时，显式建模预算，不在队列路径隐藏重新读取全局状态的循环。
- 明确区分“轮询硬件”和“消费同步状态”。原始 `poll_status()` 可以服务早期启动或纯轮询用户，但中断驱动队列不能暗中调用。

块队列适配器与 `rdif_block::HardwareQueue` 对齐：

- `info()` 暴露块大小、直接内存访问域或掩码、对齐、分段与边界约束、队列深度和 `max_submit_batch`。
- `submit_batch_owned()` 在标签、描述符和直接内存访问所有权全部保留后，只移动已接受前缀。
- 批次接受工作时，`commit_submissions()` 只执行一次硬件发布，例如一次门铃寄存器写入。
- `drain_completions()` 只在匹配中断事件后消费完成状态，不是轮询接口。
- `shutdown()` 返回或隔离全部仍可由设备直接内存访问的请求。

## 并发规则

- 对外操作需要排他访问时优先使用 `&mut self`。
- 不把操作系统锁加入可移植驱动特征。
- 任务上下文可能持有同一互斥锁时，中断处理器不能取得阻塞锁。使用非阻塞借用门控、带明确待处理状态的尝试加锁，或小型原子状态交接。
- 内部锁只保护短且不在中断中的临界区。中断上下文优先使用原子量、逐队列待处理位或明确延后排空。
- 中断端点能移入回调时，不要用 `Arc<Mutex<_>>` 或 `Arc<SpinLock<_>>` 隐藏共享。
- 任务和中断共享受锁保护的登记表时，必须采用前述排他协议并说明性能敏感路径为何不会与生命周期或结构变化竞争。
- 多个队列或端点共享寄存器块时，在一个核心对象中集中可变寄存器访问。仅在适配或运行时层用 `UnsafeCell` 等窄不安全原语，并记录排他规则。
- 硬件逻辑与同步所有权分离：原始驱动提供寄存器级操作和稳定事件快照，适配或运行时决定中断、队列、待处理状态和唤醒的同步方式。
- 不安全代码尽量局限于回调桥、内存映射构造和直接内存访问适配边界。
- 慢工作在任务、工作任务、执行任务或轮询上下文完成，不在硬中断中完成。

## 审查清单

- `src/` 是否保持与操作系统无关？
- 操作系统软件包是否只出现在开发依赖、平台适配层或明确适配软件包？
- 内存映射是否通过 `mmio-api` 或清楚的操作系统适配边界完成？
- 直接内存访问是否通过 `dma-api` 处理，并明确掩码、对齐、方向、生命周期和地址类型？
- 中断代码是否返回事件，而不是直接执行操作系统通知？
- 有状态中断端点是否由注册回调拥有，而不是通过公共 `Arc` 或锁共享？
- 控制、中断和队列端点是否分离且所有者清楚？
- 队列是否只消费队列局部同步状态，不重新读取共享或破坏性中断寄存器？
- 队列是否足够独立，可供不同通用运行时包装？
- 是否执行 `cargo fmt` 和定向 `cargo xtask clippy --package <crate>`？
