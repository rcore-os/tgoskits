# Rust 硬件与外部边界

## 1. 外部函数接口

外部函数声明要与真实调用约定、参数宽度、符号名称、可变参数和返回语义一致。进入 Rust 前验证来自外部的指针、长度、枚举值和回调；离开 Rust 时不能让恐慌跨越不支持展开的边界。

### 1.1 回调与上下文

回调上下文指针需要稳定所有者和注销协议。注销必须阻止新回调并等待在途回调结束，随后才能释放对象。不能假定外部系统在注销返回后自动完成同步，除非规范明确保证。

函数指针和上下文组合应作为一个能力对象管理，防止错配。外部保留指针时，文档说明保留时长、线程上下文和释放入口。

## 2. 用户内存

用户地址不能直接转成长期 Rust 引用。每次访问通过项目用户内存边界校验范围、权限、溢出和缺页，并处理检查与使用之间的变化。复制入内核后再解析复杂结构；复制出用户空间前不要发布部分成功状态。

系统调用的错误顺序和部分复制语义属于用户可见接口，需同时使用 `starry-syscall-compatibility`。持有不可睡眠锁时不能执行可能缺页或阻塞的用户内存访问。

## 3. 内存映射输入输出

寄存器访问使用项目内存映射输入输出能力与易失语义，不能创建普通引用后按普通内存优化。记录寄存器宽度、偏移、访问权限、保留位、写一清零和读写副作用。

### 3.1 映射生命周期

验证物理范围、页对齐、缓存属性和设备归属。映射对象必须比所有访问存活更久；设备解绑或热拔插先阻止新访问，再等待在途操作结束，最后撤销映射。

多个执行上下文访问同一寄存器时，易失读写只保证访问发生，不提供互斥或内存顺序。需要锁、屏障或设备协议顺序时显式实现并使用 `rust-concurrency-safety`。

## 4. 直接内存访问

直接内存访问缓冲区同时受处理器、设备和映射器生命周期约束。明确谁分配、映射、提交、同步、取消、解除映射和释放；设备拥有期间处理器不能以违反协议的方式访问。

### 4.1 地址与长度

区分处理器虚拟地址、物理地址、输入输出虚拟地址和客户机地址，使用类型防止混用。描述符长度、分段数量和边界使用受检算术，并满足设备对齐、最大长度和跨页限制。

### 4.2 缓存与完成

非一致性平台按方向执行缓存同步，屏障顺序与描述符发布、门铃和完成观察一致。看到完成状态后才能取回缓冲区所有权；超时不自动表示设备已经停止访问，取消和复位必须有明确协议。

驱动代码还要使用 `cross-kernel-driver` 检查队列、完成状态和操作系统适配边界；平台映射与屏障细节按 `arch-platform-porting` 处理。
