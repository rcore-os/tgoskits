# Rust 非安全契约与证明

## 1. 缩小非安全边界

先用安全类型验证长度、范围、对齐、状态和所有权，再进入最小 `unsafe` 块执行不可替代操作。不要把整个函数或模块包进非安全块，也不要通过扩大 `unsafe fn` 把实现责任转嫁给调用方。

### 1.1 指针有效性

证明指针非空要求、对齐、指向已分配对象、访问长度位于同一分配内、对象已经初始化，并在访问期间没有被释放或重新分配。整数转指针还要证明地址来源和映射有效，不能只检查数值范围。

构造切片时检查元素数量与字节长度的乘法溢出、零长度指针规则和整个范围。读取结构体前验证缓冲区长度、对齐、有效位模式和尾部填充；不可信字节不能直接转成任意 Rust 类型。

### 1.2 别名与可变性

创建 `&mut T` 需要在整个借用期内独占对应内存；硬件、设备、客户机、其他处理器或外部程序并发访问时通常不能建立普通可变引用。使用原始指针、易失访问或专用共享内存抽象表达真实语义。

从共享引用取得可变访问必须通过 `UnsafeCell` 或拥有内部可变性契约的类型。不能通过指针转换绕过 Rust 别名规则，也不能因为实际机器“看起来工作”就假定未定义行为可接受。

## 2. 生命周期与释放

返回引用或保存裸指针时证明来源对象至少存活同样久。把局部引用延长为静态生命周期、保存指向可移动容器元素的指针、或在锁释放后继续使用内部地址都需要真正稳定的所有权机制。

### 2.1 析构与部分初始化

手工分配、数组构造和外部资源登记要记录已经初始化的元素数量，失败或恐慌时只析构已初始化部分。`ManuallyDrop`、`MaybeUninit` 和原始分配接口不得产生重复析构或内存泄漏。

所有权交给外部系统、设备或另一执行上下文后，原对象必须停止释放；取回所有权需要唯一完成令牌或状态转换。引用计数不能替代设备完成、取消或解绑协议。

### 2.2 手工线程安全实现

`unsafe impl Send` 和 `unsafe impl Sync` 分别证明值可跨执行上下文转移、共享引用可并发访问。逐字段检查裸指针、外部句柄、处理器局部状态、锁和回调；存在锁不自动证明所有字段都受保护。

说明哪些同步原语保护哪些字段，以及析构是否可能与并发操作重叠。需要内存顺序或中断规则时同时使用 `rust-concurrency-safety`。

## 3. 布局与调用约定

只有外部二进制接口、硬件描述符或线协议确实要求时使用 `repr(C)`、整数表示或打包布局。记录字段顺序、大小、对齐、字节序和填充；避免读取或复制未初始化填充字节。

`transmute` 需要证明源与目标大小、对齐、有效位模式、生命周期和所有权完全兼容。通常优先使用显式字段转换、受检整数转换、`from_ne_bytes` 或专用构造函数。

## 4. 证明与测试

每个非安全操作的注释应能独立回答其前置条件为何成立，并指向附近的检查或类型保证。共享前置条件可以在安全包装器文档中集中说明，但块内仍要指出本操作依赖其中哪一项。

测试覆盖空值、零长度、最大长度、错位、截断、重复释放、并发关闭和错误回滚。能够使用解释器、地址检查或模型检查时可作为补充；这些工具未报告问题不等于证明健全。
