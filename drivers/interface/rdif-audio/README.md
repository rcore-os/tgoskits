# 通用 PCM 播放接口

`rdif-audio` 是独立于操作系统和控制器的 `no_std` 播放能力。当前调用方是 ArceOS 的设备注册适配及 QEMU 播放程序；第一个实现是 `intel-hda` 的 `rdif` 功能。接口不承担 PCI 发现、设备映射、调度、ALSA/OSS、混音、采样率转换、录音或 HDMI。

## 接口与所有权

- `Playback: DriverGeneric` 可以作为系统注册的异构设备能力，只有一个可变所有者。设备可跨任务移动，但不可复制；运行时决定串行调用和等待策略。
- `configurations()` 返回设备实际支持的完整格式与 period 配置，不把 HDA 的固定格式当成所有音频设备的默认值。调用方选择其中一项；不支持的配置在修改设备之前被拒绝。
- `prepare` 建立播放流。`submit` 接受恰好一个 period，并在返回前复制调用方样本；成功后调用方可以立即复用原切片。失败不接受本次 period。第一个提交启动播放。
- `PlaybackToken` 只标识同一设备上尚未完成的提交，不是 DMA 指针或跨设备 ID。`complete` 按提交顺序返回完成 token，每个 token 只返回一次；`Again` 表示需要回收完成或等待容量，不能当作成功。
- 该最小版本明确采用任务上下文轮询契约。调用方在 `max_poll_interval_ns()` 以内服务设备；它不是中断事件接口，也不保证低延迟。未来 IRQ 接入需要单独设计，不用周期轮询伪装成 IRQ 完成。
- 完成表示硬件已消费对应 DMA period，不自动代表输出尾部已结束。建议调用方回收全部完成后调用 `release` 排空输出尾部并停止；`release` 不丢弃已完成但尚未领取的 token，调用方仍可通过 `complete` 领取，全部领取前再次 `prepare` 会返回 `Busy`。`abort` 在确认停止后取消全部 outstanding token，再允许重新准备。
- `shutdown` 永久关闭设备；失败和析构必须继续保留或隔离仍可能被设备访问的 DMA，不能把超时当作硬件已停止的证明。

## 设计选择

准备、提交、完成、排空和取消构成可复用的播放生命周期。通用接口不应依赖特定内核的全局后端选择、ALSA/OSS 文件接口、文件系统、用户内存访问或调度实现。

只公开 HDA 专用控制器不能满足通用调用方；将完整 ALSA 迁入又远超当前的播放需求。因此采用小型 RDIF 能力，按现有 GPU/input 的所有权转移方式接入 `rdrive`，不建立第二份全局音频登记表。开放 PR #2497 提供 SG2002 麦克风采集及 ALSA 入口，与播放能力不等价；本次使用独立的 `ax-driver/playback` 模块，不覆盖其 `audio.rs`，也不复制其采集运行时。当前 dev 无等价通用播放接口。目前只有一个后端，不为未实现的录音、混音、动态格式协商或零复制添加接口。

## 验证与回滚

实际 ArceOS QEMU 程序通过 `ax_driver::playback::take_playback_devices()` 取得 `Box<dyn Playback>`，只使用本接口准备和提交音频。宿主捕获 QEMU WAV，检查声道、采样率及完整样本顺序；单独的串口成功提示不足以通过测试。取消、无效配置与关闭后拒绝也在同一用例中验证。

新能力和 DMA 生命周期属于高风险共享边界，需要维护者独立确认设计；本地验证不代表设计已获批准。驱动与接口均由显式 feature 启用，不改变默认平台音频行为。回滚移除这些 opt-in 依赖和适配即可，不涉及磁盘格式或用户 ABI 迁移。
