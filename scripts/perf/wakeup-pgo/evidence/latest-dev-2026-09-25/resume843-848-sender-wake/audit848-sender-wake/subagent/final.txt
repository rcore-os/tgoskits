## 结论（先行）

交付 **(B)**：一个新的、可证伪、纯用户态（内核字节不变）的三臂同二进制诊断，把 resume847 定位出的「sender 侧真实唤醒路径 ≈5250 ns 边际」再切成**两个互斥的大组件**：

- **D 臂（域层）** = 同一个 futex 词上有 1 个真正 parked 的 waiter，但用 `FUTEX_WAKE_BITSET` 的 mask 把它排除 → 只走桶锁 + 扫描，**完全不进入调度器事务**；
- **S 臂（调度器唤醒事务）** = 同一个 waiter、mask 命中 → 完整 sender 侧唤醒事务。

D+S 之和必须复现 resume847 的 5250 ns；据此可判定缺口落在「futex 域/等待队列层」还是「调度器唤醒事务」。我没有找到任何具备 ≥4 µs 上界的语义等价源码候选，因此不交付 (A)（理由见 §3）。

## 4. 交付 (B)：三臂同二进制 sender 侧分层诊断

### 4.1 原理

`collect_futex_wakes` 的第三个判据 `(waiter.bitset & mask) == 0`（task/futex.rs:1284）是**唯一**能构造「同一个真实 parked waiter 在场、域层全跑、但零调度器事务」的手臂：

- waiter 用 `FUTEX_WAIT_BITSET_PRIVATE(uaddr, val, NULL, uaddr, bitset=1)` 入队（`bitset` 被原样存入 bucket，见 task/futex.rs:945-990）；
- `FUTEX_WAKE_BITSET_PRIVATE(uaddr, 1, 2)` → mask=2 与该 waiter 的 bitset=1 不交 → 不 `remove`、不 `mark_woken`、不 push wake handle → `wake_batch` 空批 → 返回 0，waiter **仍 parked**；
- 随后 `FUTEX_WAKE_BITSET_PRIVATE(uaddr, 1, 1)` → 命中，返回 1 并释放 waiter。

Linux 侧路径对称（`futex_wake` 的 `plist_for_each_entry_safe` + `this->bitset & bitset` 判据 → 不 `wake_q_add`），因此**同一份用户态源码可在冻结 G 镜像与冻结 Linux RT 镜像上跑**，内核字节不变（沿用 resume847 的方法学与 SHA 校验要求）。

### 4.2 三臂与协议

`wake_cost.c` 的三次计时（同一迭代、固定顺序、各含一次尾部 `clock_gettime` 原始系统调用）：

1. `empty`：对无 waiter 的独立词（沿用 resume847 的 `state.empty`）`FUTEX_WAKE_PRIVATE(word,1)` → 期望 0；
2. `bitset_miss`：对 `gate` 词 `FUTEX_WAKE_BITSET_PRIVATE(gate, 1, 2)` → 期望 0（waiter 保持 parked）；
3. `bitset_hit`：对 `gate` 词 `FUTEX_WAKE_BITSET_PRIVATE(gate, 1, 1)` → 期望 1。

其余沿用 resume847：sender `SCHED_FIFO 80` pin CPU0，receiver `SCHED_FIFO 1` pin CPU0，receiver 成功设置策略后才 `ready`，每迭代 `nanosleep(50 µs)` 让 receiver 完成 park，20000 样本，原始 `CLOCK_MONOTONIC` 系统调用计时，warmup 1000。

**无效判定（预设，必须先判无效再算）**：任一轮 `empty_count != 0 || bitset_miss_count != 0 || bitset_hit_count != 1`、`receiver_error != 0`、`join != NULL`、样本数或直方图不符 ⇒ 该轮无效。`bitset_hit_count == 1` 本身就证明 mask 命中的那一刻 waiter 仍在同代 park 中（唯一能把它取走的只有匹配唤醒）。

### 4.3 预登记判定规则（关键，先写在 `begin()` 里再上板）

记 `D = p50(bitset_miss) − p50(empty)`，`S = p50(bitset_hit) − p50(bitset_miss)`，下标本系统。先用 resume847 的量做**内部一致性**要求：`D + S` 必须落在该轮 `p50(bitset_hit) − p50(empty)` 的近旁（同轮同二进制，直接相减即为真值），并与 resume847 的 5250 ns / 1168–1459 ns 同量级；若三臂之和与 resume847 边际差出量级，说明新协议本身改变了被测路径，应先修协议而不是解读阶段。

- **R1｜域层假设**：若 `D_starry ≥ 3.0 µs` 且 `D_linux ≤ 1.0 µs` ⇒ 缺口在 **futex 域/等待队列层**（`has_pending_waiters` 屏障、PI 睡眠互斥量、`mark_woken`、`into_wake_handle`、wake-batch）。此时应关闭调度器侧方向，改为审计桶锁的 PI-mutex 快路径与 waiter 交接（**不得**用被禁的单 waiter 快路径修）。resume604 已把 fence 排除，故 R1 会把嫌疑集中到桶锁与 waiter 交接本身。
- **R2｜调度器事务假设**：若 `D_starry ≤ 1.0 µs` 且 `S_starry ≥ 4.0 µs`、同时 `S_linux ≤ 1.5 µs` ⇒ 缺口在**发送侧调度器唤醒事务**（任务锁/rq 锁/入队/发布）。此时可断言「整段事务是可测量目标」，随后用 §4.4 的轴 2 在**同一二进制**内继续二分，而不需要任何内核探针。
- **R3｜常系数摊薄（支持关闭）**：若两个半区都低于 3.0 µs 而 `D + S` 已复现总边际 ⇒ 缺口是被摊到整个窗口的逐指令/缓存常数因子，与 resume842 §4 的结论一致，方向应按 (C) 关闭，并在台账写明「已在无插桩同二进制条件下完成 sender 侧二分，无单一主导组件」。
- 仪器下限：任何 <300 ns 的臂间差按噪声处理（resume842 给出 291 ns 时钟对底线；resume847 两轮 p50 完全重复：1750/1750、2916/2916）。至少 3 轮有效、交错次序。

### 4.4 可选（同一二进制、同一次板卡会话内）追加轴

- **轴 2｜class 维度**：把 waiter 换成 `SCHED_OTHER`（nice 0）并同样让当前线程为 FIFO80，则 [class.rs:461 起](/home/zhourui/.codex/worktrees/03ae/tgoskits-dev/components/ax-task/src/sched/algorithm/queue/class.rs:461) 的 `fair_wakeup_preempts` 对 RT current 仍返回 false ⇒ `reschedule` 依旧 `None`，但 `prepare_wake_activation` 会额外做 `current_fair_contender`/`update_fair_virtual_time`、`place_after_activation` AVL 插入、可能的 runtime-deadline 刷新。`S_fair − S_fifo` 即 **Fair 专属入队成本**（原生、无插桩），直接对应 full20 中占比最大的 OTHER 同核行。这不与 resume562-565（插桩分段）重复，因为此处没有探针开销。

## 5. 不确定项与未覆盖范围

1. **未运行任何构建/测试/板卡**；所有数值均引自 resume847 归档与台账文本，未在本轮复核板卡、频率、镜像 SHA。
2. **`bitset_miss` 臂的域层成本不严格等于 `bitset_hit` 臂的域层成本**：命中臂多出 `VecDeque::remove` + `waiter_removed()` + `mark_woken()` CAS + `into_wake_handle()`（Arc clone + external-lease 获取）。这部分被计入 `S`，因此 `S` 是「调度器事务 + 少量命中专属域工作」的上界；好在同一偏差也存在于 Linux 的 `S_linux`，判定规则只用两者的**比较**，不单独把 `S_starry` 当调度器成本。
3. **`FUTEX_WAIT_BITSET` 的 timeout 语义是绝对 CLOCK_MONOTONIC**（无 `CLOCK_REALTIME` 时）。协议必须用 `NULL` timeout（或绝对期限），不可像 `FUTEX_WAIT` 那样传相对值，否则 waiter 立即超时并使该轮无效。
4. **两系统域层并非等价成本**：Linux 的空唤醒仍执行 `get_futex_key()`（VMA/key 解析），Starry 的 Private 解析不碰 VMA（task/futex.rs:859），这解释了 resume847 中 Starry 空唤醒 1750 ns 反而快于 Linux 2916 ns；因此 `D` 的跨系统比较只能读**相对量级**，不能当作「同一份域工作的耗时」。
5. 未确认 `bitset_miss` 臂在 Linux 上是否会被 `futex_waitv`/`futex_lock_pi` 等其它机制干扰（本题只用 `FUTEX_WAIT_BITSET`/`FUTEX_WAKE_BITSET` 私有形式，应在 `begin()` 记录常量值 `FUTEX_WAIT_BITSET=9`、`FUTEX_WAKE_BITSET=10`、`FUTEX_PRIVATE_FLAG=128`）。
6. 未在源码层面确认 resume605/598/628 的分段均值在当前 head 上是否仍成立（head 与板卡均不同，按台账规则视为不可移植）；本交付不依赖它们。
