## Verdict

Read-only audit at `69a3365076` (dev `05175ca388`). **No source-provable, semantics-preserving multi-microsecond candidate exists in the `idle_current_cpu_once → wait_for_interrupt → IRQ return → tick restart → PreemptExit` segment.** The idle guard causes **no** duplicated required operation; the clockevent transaction performs exactly one reconcile per firing edge; and an IRQ-return switch *cannot* occur before tick restoration (`runtime_impl.rs:393-397` is enforced, not aspirational). The decisive point is structural: this whole segment is **byte-identical on the FIFO `absolute_timer_same_cpu` row**, so nothing inside it can explain the *OTHER-specific* ≥14 µs gate gap. Only the ktimers hop is OTHER-specific, and `resume839` already falsified a removable operation there under the ParkSoft contract. Nothing was executed; all numbers below are quoted.

## 2. The two specific tests

**Idle guard duplication — disproved.** The guard does not add work; it only moves the switch from IRQ return to the final preempt exit (`#15` vs `#19`). Both guards are load-bearing: `PreemptScope` keeps `REQUEST_IDLE_POLLING` from attaching to an ordinary task (`runtime/cpu.rs:80-86`), and the `PreemptGuard` is what makes `finish_preemption` return `Nested` instead of `Pending` at IRQ return. Removing either admits a switch with the tick still `Stopped` (see C2).

**Clockevent transaction duplication — disproved.** Per firing edge there is exactly one reconcile: `reconcile_scheduler_publication` is a no-op while `phase == Firing` (`clock_event.rs:399-405` returns `None` for `Firing`), and the single effective reconcile happens in `finish_deferred_rearm` (`#16`). The two `restart_current_scheduler_tick_after_idle` calls are **provably idempotent**: the second returns `ClockEventAction::None` when `SchedulerTickState` is already `Running` (`clock_event.rs:163-165`), so it is a pure race fallback (required when work becomes visible after the WFI checkpoint), not a duplicate program. `timer_irq_handler` explicitly declines to open a nested irq-save (`clock_event_runtime.rs:369-372`). Independent older-head support: `exp79` counted 40005 publications vs 1396 hardware comparator writes (3.49 %), 0 hits on "other physical timer write", and concluded *"Do not prioritize repeated hardware timer programming as dominant same-CPU forward cost"* (`exp79-status.json`). That is memory/artifact-derived, on head `09b977f3`, i.e. **not a current-head measurement** — it bounds the hypothesis, it does not prove the current image.

**IRQ-return switch before tick restoration — impossible, and correctly so.** During WFI the depth is ≥2, so the IRQ-return exit yields `Nested` (`preempt.rs:131-140`) and `guard/mod.rs:299-301` returns without scheduling. The only windows where a real IRQ-return switch (`guard/mod.rs:319-330`, entry `IrqReturn`) can happen are those where the idle `PreemptScope` has not yet been dropped but the tick has already been restored (`#17` runs before `#18`), i.e. never before tick restoration. Conversely, if such a switch *were* possible it would be a NOHZ violation: `tick_nohz_idle_exit()` must precede `schedule_idle()` (see the comment at `runtime_impl.rs:393-397` and `publication.rs:58-63`).

## 3. Why this sub-direction closes

The FIFO row cannot switch out of idle at IRQ return for the same reason (`#15` is shared code, entry kind is forced by the guard, not by the selected thread). So both rows necessarily traverse `#2-#9` and `#15-#21`; the FIFO row's own timeout wake is taken in the IRQ via the hard Park path (`expiry.rs:82-86` `wake_thread_from_current_cpu`) and its switch is likewise a `PreemptExit` from idle. Therefore a redundant operation anywhere in the idle guard / clockevent transaction is **common overhead across both rows** and cannot produce the OTHER-specific ≈20.75 µs (`40625.5` OTHER vs `19875` FIFO, Linux `23920` vs `13211`; per `resume839`). The only OTHER-only work is `#11-#14` (promotion + ktimer publish/notify + worker wake) and `#22-#24` (worker pass, park, second switch) — audited in `resume839`/`resume823` with no removable multi-µs operation under ParkSoft, and `resume831`'s "notify-return→frame-entry 4-6 µs" bucket is instrumented and includes this same shared segment plus IRQ epilogue. `resume839` already rejected the one magnitude-plausible lever (Fair `ParkHard`) as a contract change (`park.rs:460-476`).

## 4. Concurrency proof obligations any candidate here must discharge

- **C1 (wake-loss freedom):** for every scheduling publication `P`, either `P` observed `REQUEST_IDLE_POLLING` and was folded (`scheduler.rs:393-398`), with delivery provided by the final IRQ-off recheck reading the sticky word, or a doorbell/local publication happens (`scheduler.rs:317-325`). Must be shown to hold across the Release publish CAS (`scheduler.rs:135-141`), the SeqCst fence (`scheduler.rs:558`), and all three rechecks — not just one.
- **C2 (tick restored before leaving idle):** prove that for every idle→non-idle selection either `runtime_impl.rs:462-467` or `publication.rs:55-65` runs before `execute_switch_plan` (`dispatch.rs:91-92`), i.e. `SchedulerTickState` is `Running` at selection. Note the `OwnerSchedulerDeadline::Unchanged` early return at `publication.rs:30`; it is currently safe only because all idle→non-idle paths pass `Reevaluate` (`preemption.rs:70`), so any change must re-prove reachability of the selection-tail restart.
- **C3 (if proposing an IRQ-return switch):** must prove polling cleared and pending word observed, tick restored *inside* the IRQ-return window before `enable_irqs`, exactly-once consumption of the pending final preempt exit, and no `PreemptScope` nesting in hard IRQ (`cell.rs:476-482`). The current `finish_deferred_rearm` at IRQ exit cannot satisfy this, because the restart decision needs the post-WFI `needs_resched` observation.
- **C4 (if touching the ktimer hop):** ParkSoft classification, one-waiter-per-CPU cell ownership, publish-before-notify (`remote/ktimer.rs:119-126`), claim generation comparison and `complete()`'s conditional re-notify (`:145-158`) must all be preserved.

## 5. One precise discriminating measurement (only if someone contests §3)

Per-generation paired boundary compare with a **FIFO control in the same image/board/session**, using only these five stamps: `t0` = first scheduling wake publication inside the clock IRQ (`owner_deadline.rs:455` for OTHER, `expiry.rs:85` for FIFO); `t1` = return of `wait_for_irqs_disabled()` (`axcpu/asm.rs:103-109`); `t2` = return of `restart_current_scheduler_tick_after_idle` (`runtime_impl.rs:466`); `t3` = PreemptExit frame-enter return (`dispatch.rs:70-71`); `t4` = first instruction of the switched-in thread. Falsifier: `Δ(t0,t3)` and especially `Δ(t1,t3)` equal within noise between FIFO and OTHER ⇒ the idle-exit machinery is provably common and cheap, this direction is closed and the residual lies in `t3→t4` (dispatch/switch) plus the worker pass (`resume838/842/843/844` frontier). Only a multi-µs `Δ(t1,t3)` on OTHER but not FIFO would justify an instruction-level audit of `wait_for_interrupt`.
