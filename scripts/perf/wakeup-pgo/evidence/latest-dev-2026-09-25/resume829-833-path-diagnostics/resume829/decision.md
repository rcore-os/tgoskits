# resume829: read-only ktimer path audit

Source `69a33650763538692fafea27c869870ed0313642`, base `dev@05175ca38823b631a73777b0130226ddfa558439`. The cited idle, preemption-exit, scheduler-entry and ktimer-worker source was checked. No code was changed, built or run on a board in this experiment.

`resume828` paired publish/notify/claim for 509/495 FIFO and 11440/11439 OTHER events, but requiring an `IrqReturn` frame entry plus worker switch decision matched only 11/15 and 47/40. The probe recorded only the first `IrqReturn` frame after the notification. It therefore omits `Task`, `PreemptExit`, `IrqGuardExit`, and continuation paths, and cannot prove the first frame selected the worker. The idle path retains an outer preemption guard across WFI (`os/arceos/modules/axruntime/src/thread/runtime_impl.rs`); nested IRQ exit does not itself schedule (`guard/mod.rs`), while the idle loop calls `schedule_current_cpu()` with `Task` entry (`thread/bootstrap.rs`). This makes a non-`IrqReturn` handoff plausible for the single-thread timer benchmark, but the experiment did not directly count CPU1's current thread or scheduler entry kind at publish/claim. The relative shares of idle handoff, already-pending wake, and generation overwrite remain unknown.

`IrqNotifyResult::Notified` merges `WakeResult::Notified` and `WakeResult::AlreadyPending`, so the paired notification is not proof of a new activation. FIFO benchmark timeouts normally use the hard park path; the roughly 500 FIFO ktimer events per round are background soft timers, not 10000 benchmark timeout handoffs. The worker runs at FIFO priority 1, below the benchmark FIFO priority 80. Crucially, `irq_return_scheduler_continuations` increments only for `RuntimeSchedulerEntry::IrqReturnContinuation` (`guard/mod.rs`), so the `resume792` inference that its low count rules out the first IRQ-return frame is invalid. Do not use that older interpretation to select an optimization.

Next, a diagnostic probe should classify the **actual switch into the ktimer worker** by scheduler entry and count worker switches against same-generation claims, instead of requiring the first IRQ-return frame. It should separately identify notifications with no new activation if possible. No semantically equivalent multi-microsecond source optimization is supported by this read-only audit; no native 90% evidence changed. Latest valid uninstrumented full20 remains G1/G2 at 11/20, worst 58.00%.
