## 结论

在 exact head `69a3365076` 上，**不存在可证据支撑、单独覆盖约 5.2 µs 的语义等价运行机制**。冻结矩阵的原生数据表明缺口是**两段相当、且各自都弥散**的成本之和：约 3.2 µs 属于 futex park/wake 事务（FIFO/OTHER 完全一致），约 2.9–3.5 µs 属于切换/handoff 通路（其中 Fair 份额远大于 FIFO）。所有已隔离的叶段在插桩下都 ≤ 约 2.2 µs，因此任何叶级改动都填不满缺口。我给出证据、最大候选（含证明义务）与一个能决定攻击方向的聚焦判别实验。

## 2. 为什么单个叶段覆盖不了 5.2 µs（原生、无插桩证据）

当前 head 的冻结 full20（`resume818` G1，816 MHz，无探针）按"窗口内是否有一次切换"分层：

| 行 | Starry p50 | Linux p50 | 达标比 |
|---|---|---|---|
| getpid / clock_pair（0 切换） | 1458 / 875 | 1458 / 875 | 100% |
| futex_wait_mismatch / futex_wake_empty / sched_yield_no_peer（0 切换） | 1459 / 1458 / 2042 | 2333 / 1750 / 2625 | 115–160% |
| OTHER sched_yield_handoff（1 切换，无 futex） | 7583 | 4667 | 61.6% |
| OTHER thread_futex_same_cpu（1 切换 + futex） | 14583 | 8458 | 58.0% |
| FIFO thread_futex_same_cpu | 11958 | 8458 | 70.7% |
| OTHER/FIFO cross_cpu futex（2 切换） | 23916 / 22459 | 16041 / 13708 | 61–67% |

两点硬结论：

- **所有含 ≥1 次切换的行都失守（58–71%），所有零切换行都在 100–160%**。syscall/trap 入口出口、时钟读取、`futex_wake_empty` 等不含切换的路径没有缺口 —— 缺口完全落在切换/handoff 与 park/wake 组合上。
- **按既有行做原生差分**（用 `yield_no_peer` 作零切换基线）：Fair 的"一次 yield 切换"边际成本 Starry 5541 ns vs Linux 2042 ns（+3.5 µs）；FIFO 仅 2042 vs 1458（+0.6 µs）。而"futex 减去等价 yield"得到 park/wake 事务增量 Starry −3209 ns、FIFO −3208 ns（两者**完全一致**）。即约 3.2 µs 是 FIFO/OTHER 共有的 futex park/wake 成本，约 2.9–3.5 µs 是切换通路、其中 Fair 份额最大。（`sched_yield_handoff` 是自旋交接，这一差分是近似，非严格因果。）

插桩叶段给出的上界（都含读钟探针，不可折算收益）：整次切换三段独占阶段 2170+1143+657 ≈ 3971 ns/次（`resume606`：prepare_entry ~1150、raw_switch ~640、switch_out_hook ~370）；唤醒侧 `resume777` 最大叶 pick 2189 / enqueue 1538 / commit_selection 1101 ns；receiver 侧 `resume628/629` ax-task tail ~1996、futex cleanup ~2020 ns，其中最大子叶 1287 ns。**没有任何叶段 ≥2.2 µs**，而探针地板约 100–290 ns/边界。

因此：缺口是"多段几百 ns 相加 + 每次切换的固定公共成本"，不存在一个天然可删的微秒级操作；跨 wake→schedule 复用已被 `resume806` 证明不成立（`put_prev` 改变集合、边界是 IRQ 可用解锁窗口）。Fair V 重锚（`activation.rs:51/177`、`current.rs:56/65`、`class.rs:238`）每次 ~234–261 ns，且 exp120 已否决。`update_virtual_time` 常路径是 64 位除法，不是宽除法热点 [fair_queue.rs:659](/home/zhourui/.codex/worktrees/03ae/tgoskits-dev/components/ax-task/src/sched/algorithm/fair_queue.rs:659)。FIFO 路径甚至比 Linux 更快（零切换行 115–160%），排除了 syscall/trap 层。

## 3. 最大候选（transaction-level，量级仍不足，需组合）

唯一在结构上"够大且语义可证"的方向是**跨 Lazy 边界的带校验预选/直接交接**：唤醒侧已算出 `WakeeSelected` 与 `earliest_eligible`；调度侧可携带(wakee, 当时 V/资格快照)，在 `pick_task` 前用一条**失效协议**校验（无更高类可运行、无并发 Fair 入队改变加权均值、`protected_fair_current`/切片保护未变、无迁移请求、无 tick 提升），校验通过则跳过 `pick_eligible` 摘取与重平衡，失败则回落完整 pick。

证明义务：①校验必须覆盖 §1 所列全部并发写入者（IRQ tick `accounting.rs`、`on_run_queue`、`bandwidth`、远端 push/pull、迁移、`tighten_current_fair_slice_protection`）；②通过时必须与完整 pick 选出**同一实体**且写入同样的 slice protection；③不得改变 `put_prev` 重插后的 EEVDF 资格。
量级上限 ≈ pick(2189) + commit_selection(1101) 的探针包含值，去探针后大概率 1–1.5 µs —— **单独不足以补 5.2 µs**，只能在判别出"Fair 决策是主项"后才值得做。`resume806` 已否掉无失效协议的复用；若重开必须写明与该结论的实质差异。

## 4. 聚焦判别实验（推荐先做，非重复）

**用 benchmark 副本（不改冻结 hash、不插内核探针）把"抢占/切换机器成本"与"Fair 决策成本"分开**：新增一行 `thread_futex_same_cpu` 的 FIFO 变体，sender 低优先级 FIFO、wakee 高优先级 FIFO，使唤醒**强制发生 RT 抢占**（与现有 FIFO"自愿阻塞后切换"、OTHER"Fair 唤醒抢占"三者对照）。

- 若 Starry 强制 RT 抢占仍 ≈ Starry 自愿阻塞（~11–12 µs，远高于 Linux 8.5 µs）→ 缺口在**抢占/切换公共机器**，攻击 §1 的 `execute_switch_plan`→incoming tail→扩展钩子链。
- 若 Starry 强制 RT 抢占 ≈ Linux（~8.5 µs）→ 缺口在 **Fair 专属的 put_prev/selection/记账**，再做 §3 的带校验预选。
- 每项须同镜像、cpufreq-off、同一冻结协议、`samples==attempted`、`not_parked==0`。

次级判别（若需量化 park/wake 那一半）：同形态副本中把 receiver 由 park 改为在 gate 上自旋（零 futex 事务、仍一次切换）；先验预测该副本超额应落在 `sched_yield_handoff` 量级（约 +2.9 µs），用于确认 §2 的 ~3.2 µs park/wake 份额。
