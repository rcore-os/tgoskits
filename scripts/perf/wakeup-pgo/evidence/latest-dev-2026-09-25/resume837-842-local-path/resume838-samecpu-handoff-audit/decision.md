# resume838: OTHER same-CPU futex transaction audit

The independent read-only trace is `subagent/final.txt`, checked against `syscall/sync/futex.rs`, `task/futex.rs`, `ThreadWakeBatch` and the frozen benchmark source. The measured forward path is sender timestamp, `FUTEX_WAKE_PRIVATE`, scheduler wake, one required same-CPU switch, receiver `FUTEX_WAIT` return and its clock read. Private wake key validation is `access_ok` rather than a VMA walk; `ThreadWakeBatch` is allocation-free. These are not hidden multi-microsecond opportunities.

G1/G2 OTHER same-CPU futex p50 is 14583.5 ns against Linux RT 8458 ns, so 90% needs a reduction of about 5186 ns. OTHER `sched_yield_handoff` is 7583 vs RT 4667 ns and FIFO same-CPU futex is 11958 vs RT 8458 ns. The cross-scenario differences are suggestive of both generic park/wake and Fair scheduling overhead, but they are **not** isolated causal costs because yield and futex have different control flow and preparation. Prior leaf probes are heavily instrumented; no measured leaf can be promoted into a promised native 5.2 us gain. `resume806` already rejects unguarded reuse of the wake-time Fair candidate after `put_prev` changes the runnable set.

The next discriminator is a separate, unhashed-for-acceptance benchmark variant on the unchanged G image: keep the sender FIFO 80, make the receiver FIFO 81, and compare a forced wake preemption against the frozen equal-priority FIFO path and OTHER path in the same boot. Repeat on frozen Linux RT before attributing a cross-OS difference. Preserve the original frozen binary and its SHA. This is diagnostic only; any later runtime candidate still requires source-matched cpufreq-off full20, all p50/p99/p99.9 regressions below 3%, zero `not_parked` and missed deadlines, and three valid candidate boots for final acceptance.
