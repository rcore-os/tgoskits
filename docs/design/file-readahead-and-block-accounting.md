# 文件异步预读与设备 I/O 统计

## 1. 顺序读取

已有页缓存按缺页触发最多 32 页的同步填充；顺序读下一窗口时仍要等待后端。`ReadAheadState` 现在记录最近成功填充的窗口，前台读取经过窗口中点后，让 `PrefetchWorker` 提前加载下一窗口。预读与需求读取共用 `PendingFills`，不建立第二套页缓存。

### 1.1 触发与预算

`prefetch_after_read()` 只在可阻塞运行时存在、文件不是纯内存文件且读取仍顺序推进时请求预读。每个窗口通过 `PrefetchRequest` 预留一个推测任务，任务结束或丢弃自动释放预留；随机访问清除顺序状态。工作队列最多保留 16 个窗口，每窗口最多 32 页。磁盘文件的 `disk_reclaim_target()` 下限为 512 页，已大于两个最大窗口；这里没有额外的小缓存分支，也不把保留目标当作当前可用内存。队列饱和、分配失败或 worker 启动失败只放弃本次尝试，后续窗口内的顺序缓存命中仍可重新触发，前台照常按缺页加载。

下一窗口同时受文件末尾和 `u32` 页号边界限制；到达可表示上限就停止预读。任务执行端再次拒绝空窗口和无法转换的起始页，不能将高位截断后误读第 0 页。

`PrefetchWorker` 在安装文件系统运行时时尝试创建一个内核后台线程；启动失败由 `os::install()` 记录原因，后续可阻塞的预读请求会再次尝试。`start()` 在同一睡眠互斥锁下检查和发布资源，成功后复用通知对象和线程句柄，不重复创建线程；失败不发布资源，也不影响已完成的需求读。请求阶段再次失败只释放本次窗口预留，不重复输出启动警告。

前台复制完数据并释放页缓存锁后入队，再通知后台线程。后台取出任务后释放队列锁，再访问文件系统。线程句柄和通知由全局 worker 保留，生命周期与文件系统运行时一致。

### 1.2 并发发布

`fill_page_window()` 在短暂的 inode I/O 临界区登记填充所有权，后端读取在锁外执行，发布前重新验证该所有者是否因写入、截断或映射更新而失效。过期填充不会覆盖当前数据。已存在填充或达到填充容量上限时，推测请求直接跳过并释放预留，供下次顺序命中重试；需求读取仍使用原有等待与重试行为。`prefetch_page_window()` 在最多 32 页内跳过已缓存的前缀和内部页，继续填充缺失部分，不把第一页命中当作整个窗口完成。

预读失败会结束其填充所有权并唤醒加入者，让需求路径重新尝试真实后端读取，不把推测任务的瞬时错误直接传给后续读取。只有整个窗口完成后，`ReadAheadState::prefetched()` 才推进触发窗口；它按原窗口 `Arc` 身份核验，旧任务不能覆盖随机跳转或新需求填充产生的状态。预读持有 `CachedFile`，因此文件、位置和缓存所有者不会在任务完成前释放。并发删除或卸载仍受既有所有者准入约束，预读没有新增绕过关闭流程的入口。

## 2. 设备计时

`DeviceIoMetrics` 属于一个 `BlockDeviceHandle`，代替原先将全局请求计数放到根设备名下的做法。`RequestAccounting` 随唯一 `CompletionSender` 移动，统计生命周期覆盖运行时准入、软件排队和硬件完成，不由等候线程是否继续等待决定。旧全局 `block_io_stats()` 及其四个累计计数已删除，NVMe 回归通过 `root_block_stats()` 使用根设备句柄的同一份统计，避免跨设备累计值掩盖未发生的目标设备 I/O。

### 2.1 统计口径

`RequestAccounting::new()` 在参数校验和运行时准入成功后启动计时，随后进入软件通道；完成被消费时终止计时。因此软件通道等待、hctx 调度和驱动拒绝后的重试均计入。准入前拒绝不产生统计。接收端取消不结束计时；入队前取消或返回原请求时，发送端析构撤销在途状态并结算已观察的忙碌区间，不增加完成次数、退役扇区、完成耗时、失败数或加权时间。已入队请求的关闭、硬错误及协议错误经 `CompletionSender::complete()` 终结。

`BlockIoStats` 使用单调时钟纳秒和 512 字节扇区。读、写、flush 分别累计请求数和时间；在途数与忙碌区间只计普通读写请求，加权时间是已经完成的读、写和硬件 flush 延迟之和。快照推进忙碌区间，不提前累加未完成请求的加权时间。

`RequestOp::Flush` 表示硬件 flush 命令，对应 Linux v7.1 的内部 `flush_rq`，不等于其上层 `REQ_OP_WRITE | REQ_PREFLUSH` 空写请求；后者在 Linux 中仍参与普通 write/inflight 记账。本接口没有凭空增加一条上层空写。Linux 的 `blk_account_io_flush()` 独立累计硬件 flush 次数与延迟，本实现按同一层次分开记录。

扇区表示终结的请求字节，不表示成功传输字节。Linux v7.1 的 `blk_update_request()` 无论状态成功还是失败，都会将本次终结的 `nr_bytes` 传给 `blk_account_io_completion()`。本接口 `CompletedRequest` 只支持整个请求的一次终态，没有中途部分完成；因此错误终态同样记录完整请求扇区，同时增加失败数。不能据此断言这些字节已经写入介质。

### 2.2 用户态呈现

StarryOS 的 `render_diskstats()` 将根块设备快照按 Linux 字段顺序输出，时间转换为毫秒，合并与 discard 字段保持零，因为当前路径没有相应操作计数。时间覆盖本内核准入到终结的延迟，不能称为纯介质服务时间。忙碌时间按单调时钟统计区间并集，Linux 使用 jiffies 更新 `io_ticks`；两者不承诺逐位相同。统计边界参照 [Linux v7.1 blk-mq.c](https://github.com/torvalds/linux/blob/v7.1/block/blk-mq.c)、[blk-flush.c](https://github.com/torvalds/linux/blob/v7.1/block/blk-flush.c) 和 [genhd.c](https://github.com/torvalds/linux/blob/v7.1/block/genhd.c)。

`root_block_stats()` 在根不是块设备（如内存根）、根设备记录尚不可用或其 `Weak<BlockDeviceHandle>` 无法升级时返回 `None`；`render_diskstats()` 随之返回空字符串，因此成功读取 `/proc/diskstats` 会得到零行。空结果表示当前没有可导出的根块设备快照，不能据此推断 I/O 活动为零、系统没有磁盘或读取失败；读取失败仍由打开和读取操作的错误返回判断。该接口不枚举其他磁盘，也不补造全零的 `blk0` 行。

监控消费者应将空结果标为“无数据”，清除此前的计数与速率基线，不延续旧速率，也不猜测设备行；设备行重新出现后，先按设备身份建立新基线，再用后续有效样本计算速率。`apps/starry/monitor` 的 `GlancesHeadlessCarpet.py` 与 `NodeExporterCarpet.py` 当前要求 NVMe 根盘 `nvme0n1` 的非零启动读计数，不覆盖空结果及恢复后的速率计算；本次仅明确接口约定，没有修改这些消费方。

## 3. 设计选择

保留单一后台预读线程可以限制 speculative I/O 对需求读和编译任务的影响。直接在前台同步读取下一窗口会扩大缓存命中路径的尾延迟；为每个文件创建线程会让大量 crate 文件带来无界线程数。独立第二套缓存会重复失效和关闭协议，故沿用现有 `FillOwner`。

### 3.1 预期收益与风险

收益来自计算与下一窗口 I/O 重叠，以及已有块队列可以接收多个独立请求。收益大小取决于顺序比例、缓存命中和实际设备并行度，不能由最大窗口和队列深度直接推算编译加速倍数。预读可能读取未消费的数据，因此限制窗口和队列，并用真实冷编比较读扇区、忙碌时间与总时间。

### 3.2 验证边界

组件用例用首次线程创建失败的隔离运行时，验证后续顺序请求经过真实启动、入队和通知路径恢复，连续窗口复用同一 worker，前台不增加后端读取，执行预读任务后可被需求命中。该用例手动执行真实 `PrefetchJob`，不启动宿主线程，不证明内核运行时的调度与唤醒时序。队列满、启动失败、后端错误以及映射和填充争用用例验证窗口重试；另一个文件句柄预填前缀后，任务仍应填充缺失尾页。设备计时用例验证普通读写与硬件 flush 的不同在途边界、完成后加权时间和错误终结扇区；单硬件槽集成用例验证软件通道中等待的第二个请求已经可见。完成通道用例验证接收端取消后仍准确终结、入队前撤销不增加完成次数、扇区、完成耗时、失败数或加权时间；真实异步提交的满队列取消和 NOWAIT 返回复用同一判定。已有填充回归继续保护并发写入、截断、映射与卸载语义。

组件用例之外，定向系统测试负责核验真实文件读写、私有映射和关闭路径；具体提交的执行结果与未覆盖项记录在对应 PR 验证材料中。板卡性能比较使用同一份源码、Cargo.lock、工具链、Linux 构建的 tg-xtask 与新建 target 目录；失败运行不能纳入成功性能数据，也不能把组合分支的收益归为单项改动。
