# VMA 空闲地址搜索优化

## 问题和范围

基于 dev 1f408d1cff3cc251157829f5cfd19e91a53ad56c。Starry 的地址空间已经使用持久化 AVL VMA 树，但 find_free_area 仍通过完整中序迭代寻找地址，逐项克隆快照。mmap 的提示地址搜索成功后，Option::or 仍无条件执行备用搜索。大量短寿命映射的编译进程会反复支付这个成本。

将旧实验的最大空洞剪枝思路迁移到当前 VmaMap，而不是恢复已经被替代的 MemorySet 状态管理。保留当前缺页准备/发布事务、物理页所有权、TLB 回收、映射权限与错误顺序。不引入新页表机制、不修改缺页预读、不新增公开 API。

成功标准：返回与现有首个对齐空闲区间规则相同的地址；跳过不可能满足申请的子树；旧快照不受插入、删除、拆分和合并影响；失败不修改任何状态。没有完整编译前后测量，不声称编译速度提升百分比。

## 既有实现、Linux 与替代方案

上游已经有锁外缺页准备和事务式发布。开放 PR #2000 处理文件私有缺页预读，#2009 处理中间页表回收失效；本改动不修改这些路径。上游范围查询剪枝不等价于空洞搜索，本次复用其持久化树与路径复制构造点。

Linux 基准为 980ab36ae5972c83f683b939e50c469c4947229e。
[mas_anode_descend](https://github.com/torvalds/linux/blob/980ab36ae5972c83f683b939e50c469c4947229e/lib/maple_tree.c#L4289-L4348)
按子树最大空洞决定是否下降；
[mas_empty_area](https://github.com/torvalds/linux/blob/980ab36ae5972c83f683b939e50c469c4947229e/lib/maple_tree.c#L4493-L4545)
在边界内寻找最低可用地址。借鉴剪枝与单一索引所有者，不复制 Maple Tree，也不宣称替换了完整 Linux 地址布局策略。

| 方案 | 取舍 |
| --- | --- |
| 保持完整遍历 | 简单，但请求成本随 VMA 数量增长，无法解决已确认的搜索路径问题。 |
| 另建可变空洞树 | 能剪枝，但需要与持久化根同步，并给失败回滚增加第二份状态。 |
| 在现有节点派生空洞摘要 | 选用。插入、旋转和删除都经过同一构造点，摘要随后继根一起发布。 |
| 替换为 Maple Tree | 扩大数据结构、所有权和迁移范围，当前需求不需要。 |

## 不变量和代价

每个不可变节点记录子树首地址、末地址和内部最大原始空洞。摘要完全由节点及两个子树派生，不公开独立修改接口。子树无重叠且地址排序，减法有序；所有申请长度与对齐运算继续使用受检算术。

搜索只借用节点，不分配迭代栈，不克隆每个 VMA。先检查子树之前的空洞，再按地址顺序搜索；内部最大空洞小于请求长度时，可将游标直接推进至子树末端。对齐后的候选仍需校验实际空洞与上界；原始空洞摘要可能导致额外下降，但不得误判有空间。特殊对齐情况下不承诺严格对数复杂度。

每个节点增加三个机器字的摘要，路径复制时增加常数次比较。没有新锁、原子变量、后台任务或状态发布点。mmap 的备用搜索改为惰性调用，不改变首选或备用地址规则。

该改动位于内存管理边界，按高风险处理；合入前先审核本文，再审查实现。实现仍留在单一 VMA 树所有者中，避免为摘要建立独立可变子系统。回滚只需恢复代码，无持久数据迁移。

## 验证

复用现有 VMA 组件测试，增加会在完整遍历上失败的有界搜索验证，并以独立空闲区间枚举判定首个候选。覆盖路径复制、移除后空洞合并、半开上界、对齐与整数溢出。节点访问计数仅用于算法复杂度回归，没有运行时采样或公开计数接口。

按接口/算术、派生摘要/生命周期、最终差异/测试输入三轮静态检查后，使用 cargo xtask test --since 执行实际选中的组件测试，再用 8c8g Starry QEMU 的既有 mmap、mremap、shmat 与 AIO 用例验证装配。未执行部分必须明确列出，组件测试不能代替系统调用证据。
