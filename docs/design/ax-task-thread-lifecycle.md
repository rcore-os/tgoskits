# 线程装配与 Linux RT 生命周期

## 1. 语义基准与分层

本设计的语义基准是固定提交的 Linux v7.1，启用 PREEMPT_RT 配置。对照的是创建、发布、唤醒、切换和回收的顺序与责任划分，不要求复制其 C 对象布局；每条调用路径都必须同时说明发布者、观察者和资源释放责任。用于阅读基准的本地源码树若未启用 RT 配置，只能作为代码结构参考，不能当作 RT 运行或性能证据。

### 1.1 所有权分层

核心调度组件（ax-task）拥有调度状态和公共线程执行生命周期；运行时装配层（ax-runtime）提供架构资源装配；StarryOS 的线程对象持有 Linux 每线程状态并引用共享的进程数据。操作系统扩展直接安装到线程规格上，不经过内核线程或运行时线程的外层扩展转发。公共创建统一走装配器（builder）入口，运行队列和唤醒句柄保持非泛型，避免把操作系统差异扩散进调度器。

### 1.2 顺序对照

Linux 顺序是迁移验收条件。下表给出两侧的对应关系，每一行都要求同时验证发布者、最终所有者和顺序场景；具体验证状态见第 10 节。

| Linux 基准路径 | 本项目入口 | 最终所有者 | 顺序要点 |
| --- | --- | --- | --- |
| 任务结构复制与进程复制（dup_task_struct/copy_process/sched_fork） | 装配器、创建入口、未发布上下文 | 核心创建事务与运行时资源装配 | 完整初始化后保持“新建”状态；逐阶段回滚、提前普通唤醒 |
| 新任务首次唤醒（wake_up_new_task） | 装配线程（staged thread）的预留与激活 | 登记表中的激活预留与目标 CPU 接收端 | 身份发布后首次激活；暂存期间亲和性与策略更新、快速退出、取消不执行入口 |
| 进程复制错误退出 | 发布取消与回收处理 | 唯一创建令牌转交任务上下文回收器 | 中断内丢弃引用不取登记表锁；无管理句柄的取消与扩展一次性析构 |
| 唤醒与 RT 互斥调度（try_to_wake_up/rt_mutex_schedule） | 生命周期等待状态与 PI 等待令牌 | 等待状态、PI 拥有者与运行队列 | 普通通知和锁交接分离；RT 外层超时、读者排空、远端唤醒 |
| 上下文切换与切换尾部（context_switch/finish_task_switch） | 切换计划与运行时切换尾部 | 运行队列提交；物理上下文；进入方尾部 | 读取前一任务终态后再释放离 CPU 引用；多处理器切出、迁移与四类地址空间交接 |
| 调度尾部（schedule_tail） | 公共跳板 | 公共执行对象与运行时接力棒 | 首次入口、阻塞恢复与让出后验证中断与阻塞许可 |
| 任务栈与任务结构释放（put_task_stack/put_task_struct） | 退出执行对象取走与任务工作消费者 | 资源、操作系统扩展与 active-MM 各自的所有者 | 管理句柄不保留退出栈；原子上下文直接回收被拒绝；惰性 MM 在最后一个 CPU 租约退出后释放 |

切换尾部先读取退出状态，再清除“在 CPU 上”标志；任务引用与内核栈引用具有不同寿命。Linux RT 通过延迟释放避免在原子上下文取得睡眠锁，本项目复用任务上下文回收器，并对每个被借用对象单独证明读者保护。

### 1.3 锁等待边界

普通互斥锁保持普通 PI 等待。RT 自旋锁与 RT 读写锁使用独立的 RT 锁等待语义；原不可睡眠实现以“raw 锁”命名区分。普通锁、RT 锁和 raw 锁不能仅按接口形状互换：中断处理、调度交接和已有抢占保护中的调用方必须显式使用 raw 类型。

线程生命周期的一个原子状态字同时保存物理调度状态、内层通知和外层状态。RT 锁持有期间，普通唤醒只更新保存的通知；锁交接通过独立的唤醒来源更新内层状态，才能激活内层阻塞。PI 交接唤醒在等待锁内捕获 PI 代次，交接延迟到下一次等待时不会误唤醒新等待者。读写锁的读者排空使用独立的内层停车代次。

外层停车票据的代次保存在线程核心中；内层停车使用单调递增的代次序列，不能恢复计数器而复用旧代次。硬、软和同步超时到期路径都比较普通等待代次，避免内层停车覆盖外层超时。外层状态与票据在调度锁下恢复，外层通知使随后的提交解除阻塞，而不是重新丢入运行队列。

### 1.4 锁类型与上下文

锁对象的 Rust 借用保护被锁数据的有效期；调度侧迁移钉住、RT 临界区深度和等待状态分别表达不同约束。RT 临界区守卫只禁止普通睡眠，不禁止抢占或另一把 RT 锁的竞争调度；它不是通用 RCU 宽限期实现，不能用其计数或共享引用计数替代逐对象读者证明。Linux 对照范围包括 RT 自旋锁、RT 读写锁底座、RT 互斥锁、信号量和本地锁内部实现，以及核心调度路径。

| Linux RT 对象 | 本项目对象 | 等待与交接 | 持有期间 |
| --- | --- | --- | --- |
| raw_spinlock_t | raw 自旋锁、raw 读写锁 | 原子自旋；不做 PI | 普通方法关闭抢占；保存中断版本同时关中断；非钉住版本由 unsafe 调用方提供保护 |
| spinlock_t | RT 自旋锁 | PI 门禁，保存外层状态的 RT 锁等待 | 可抢占，禁止迁移及普通睡眠；保存中断拼写不改变硬件中断 |
| rwlock_t | RT 读写锁 | PI 写者门禁，等已有读者排空 | 同 RT 自旋锁；不能向多个已有读者捐赠优先级 |
| local_lock_t | 本地锁 | 先钉住 CPU，再选择每 CPU 锁，再取得 RT 自旋锁 | 同 CPU 任务可抢占竞争；解锁后释放外层钉住 |
| mutex | 互斥锁及可中断扩展 | 普通 PI 等待，取消谓词与交接竞争 | 普通可睡眠任务上下文，不自动钉住 |
| rw_semaphore | 读写信号量 | 与 RT 读写锁共用写者门禁和读者排空，使用普通等待 | 不自动钉住；已有读者完成后才允许独占 |
| semaphore | 信号量 | raw 中断安全 FIFO，直接交付许可，不做 PI | 唤醒与尝试获取可在中断调用；阻塞、超时和中断等待只在任务上下文 |

信号量登记在同一个 raw 锁下裁定取消与授予；队列扩容在任务上下文分配，中断端不销毁等待者对象。

### 1.5 迁移禁止

线程亲和状态区分请求掩码与有效掩码。首次迁移守卫在登记表、线程调度锁和拥有者运行队列事务下安装预建的单 CPU 掩码，并刷新所有调度类的迁移候选索引；嵌套守卫只增加深度。外层释放恢复最新请求，并投递拥有者调和。CPU 下线在同一登记表锁下拒绝仍有钉住的 CPU。

锁获取后建立 RT 临界区和迁移保护；释放按“恢复迁移许可 → 结束 RT 临界区 → PI 解锁”排列。普通管理引用不是迁移保护。远端调度亲和设置使用异步请求，只有目标 CPU 满足新掩码后请求才完成。

## 2. 创建事务与资源装配

创建令牌拥有取消责任，登记表拥有已转交资源。装配分为三个阶段：准备（资源齐备、保持未运行）、装配（完成可失败准入的发布事务）、激活（一次性进入可运行状态）。队列节点在构造阶段预留；CPU 下线、亲和性修改和远程投递必须与最终激活串行。

### 2.1 装配与激活

装配阶段在登记表和线程调度锁下选择目标 CPU，把激活预留保存在登记记录中；该预留持有目标 CPU 接收端和收件箱投递租约，CPU 下线必须等待已有租约退出。亲和性修改先预留新目标，再替换旧预留，失败不提交新亲和性；策略修改仍由原调度所有者处理，激活前刷新预留投递的负载信息。

激活在中断与抢占保护下消费预留，只执行一次从“新建”到可运行状态的转换。身份发布后的正常路径没有可恢复错误；运行时未安装等违反契约的情况作为不变量失败处理。低层启动入口复用同一准入协议，拒绝绕过持有公共执行对象的创建令牌。

装配线程或准备线程被丢弃时，只把预分配的取消节点和一个强引用投递给现有任务工作收件箱，不在硬中断或原子上下文取得登记表锁。回收器先取走并在锁外释放预留，再标记“未入队已退出”，把未调用的入口闭包交给任务上下文退出回调释放；并发调度控制仍忙时保留请求重试。公共的退出标记与启动入口都拒绝受管线程，维护创建令牌的唯一所有权。

### 2.2 浮点状态继承

子线程首次执行时必须观察到父线程已有的浮点状态，装配不能只复制通用陷阱帧。非 RISC-V 架构的继承集中到运行时装配层的未发布资源阶段：x86_64 沿用惰性扩展状态所有权处理；AArch64 与 LoongArch 在 soft-float 内核中于 CPU 钉住下把当前 CPU 的 eager 浮点状态快照进未发布子上下文；RISC-V 保留显式寄存器快照与 FP 状态字。统一配置入口让各架构选择“继承当前浮点状态”或提供显式快照，实际保存仍由运行时在原准备阶段执行，配置收敛不取消架构差异。覆盖范围是当前支持的标量浮点与现有 SIMD 保存格式，不宣称新增 SVE、SME、LSX 或 LASX 支持；验证方式是四架构子线程第一段代码读取预先写入寄存器的真实断言。

### 2.3 失败回滚与内存不足分类

用户上下文装配在第一次分配前建立未发布上下文；成功时转交完整资源，失败时由同一任务上下文依次释放架构上下文、TLS 和栈。地址空间在完成架构初始化前仍由配置持有，任何失败都不能遗失它的唯一所有权。执行资源释放遵循一次性消费契约，不恢复旧的“忙/重试”状态；虚拟栈关闭失败时的隔离区由内存子系统独立持有，不能重试已经消费的栈句柄。

创建路径不得在持有运行队列锁或关中断时分配。运行队列的成员位图、公平类、期限类和可推送索引按配置的线程容量在初始化时预建，登记槽、空闲槽和退出候选同样在锁对象投入使用前预留容量；创建、唤醒及迁移不再扩容这些索引。代价是每 CPU 提前承担配置上限对应的索引内存。线程槽耗尽与堆分配失败保持不同错误：前者返回 EAGAIN，后者返回 ENOMEM，其余运行时故障保留原分类（BadState/EFAULT）；这与 Linux 在线程数量限制检查先于分配失败检查的顺序一致。

对象分配统一使用可失败的标准分配（盒子、共享指针、向量精确预留），沿结果链传播；栈描述符先分配盒子再取得实际栈存储，成功后才完成对象写入，使描述符分配失败不遗失已取得的栈。槽预留统一拥有未发布槽的代次和期限类准入额度；私有对象分配失败时先撤销槽与额度，再释放资源及直接操作系统扩展，只有登记表提交成功才解除回滚责任，失败路径不运行新线程入口。

操作系统层的创建前置状态同样可失败：线程扩展、共享名称快照（先精确预留字符串内容，再建立共享快照）、信号管理器、安全组件首快照都沿既有错误链返回；进程的子线程登记采用“锁外预留、锁内重新验证并发布”的顺序，预留失败返回 ENOMEM。一次性引导的致命失败策略明确保留，不据此宣称所有系统初始化分配都可恢复。默认亲和性交给公共装配器的可失败默认分配，不再提前构造全 CPU 掩码。

### 2.4 安全状态的最终继承

线程组安全状态（seccomp 过滤器、no_new_privs、syscall-work）的继承与同步共用一把进程级任务上下文 PI 门禁：安全安装、线程组同步（TSYNC）和 clone 的最终发布都串行经过它。clone 在资源准备、装配以及可回滚的 cgroup/拓扑准备完成后，才执行最终安全继承并发布 PID、附接任务和加入线程组；解锁后才安装已预留的 pidfd、通知和首次激活。

这条边界保证 TSYNC 先完成时 clone 继承新状态，clone 先发布时 TSYNC 的成员扫描包含子线程。锁顺序为进程安全更新锁、每线程快照存储锁（复制后释放）、PID 发布锁及线程组成员锁；新锁只用于可睡眠任务上下文，不模拟 raw 运行队列锁，也不改变中断、迁移或调度交接。TSYNC 同步过滤器时同时传播调用线程的 no_new_privs，防止线程组通过安装过滤器的线程退出而绕过该限制。

最终继承本身可失败：快照存储在发布指针前执行可失败预留，失败返回 ENOMEM，原快照与标志均不改变，发布回调不执行，外层创建令牌撤销资源。exec 的身份转交发生在同组其他线程退出后，退出请求只在系统调用返回用户态前处理，已经开始的同步 TSYNC 会先完成；因此不在 exec 的兄弟退出等待外再套安全更新锁，避免持锁等待正在取得同一锁的兄弟线程。

### 2.5 发布期间的外部修改

线程身份可在激活前被其他线程看到，因此装配期间的策略和亲和性修改必须保持可用。公共调度接口对“新建”线程的更新在真实调度器下验证；系统调用层保留各自的用户内存、权限和参数校验。远端亲和请求只有在目标 CPU 满足新掩码后才完成，见第 1.5 节。

### 2.6 文件描述符准备事务

可失败创建的统一顺序是：先预留描述符编号，再在文件表锁外调用可失败的文件工厂，最后安装；创建失败、结果复制失败和取消都撤销原表中的预留，安装后的析构不会删除已被其他线程关闭并复用的编号。准备状态区分“已预留”“就绪”“已安装”：查找、关闭和枚举只观察已安装项；dup2/dup3 对预留项返回 EBUSY；复制文件表只复制已安装文件；文件析构始终在本次准备事务释放表锁之后执行。文件表直接在内联槽和位图中保存预留与已安装状态，不再维护第二份预留集合。

socketpair 遵循相同边界：先检查非法类型标志，预留两个编号，在锁外完成两个结果复制，再创建套接字和文件，最后逐项安装；任一阶段失败由守卫撤销预留，套接字与文件析构不在文件表锁内，两个文件引用的可失败分配映射为 ENOMEM。接收消息携带描述符（SCM_RIGHTS）复用同一准备入口。

用户内存写回时机按 Linux 语义分两类，不能合并为一项创建前预检查：pidfd 的输出指针错误属于发布前检查，编号耗尽先报 EMFILE，坏指针在预留之后、身份发布之前报 EFAULT，不发布孩子；parent_tid 属于发布后尽力写，孩子已发布，写失败不撤销创建。空指针输出同样必须进入准备和写回流程，不能被当作“未请求”。

### 2.7 内核服务创建入口

内核服务线程统一通过公共装配器入口创建，由薄封装设置操作系统默认栈大小，不再以组合函数重复表达装配参数；等待直接消费公共连接句柄，后台服务仍由调度器拥有执行责任。闭包内容、唤醒协议、中断状态和发布顺序不受入口收敛影响。

## 3. 执行、完成与回收

切换尾部释放 CPU 所有权后，任务上下文回收执行资源。操作系统扩展由强句柄和在途回调保护，最终析构不能提前；active-MM 令牌由独立的最后 CPU 回收协议处理。逻辑退出通知不代表线程已经物理切出，也不代表最终引用已经消失。

### 3.1 完成交接

公共执行对象是唯一的公共入口、返回码和完成等待所有者。正常返回与显式退出当前线程都先发布逻辑完成，再提交退出调度；等待只承诺返回码可见。连接遇到仍在切出、仍有回调或其他租约的线程时，把最终回收交给回收器，不等待无关引用归零。

公共跳板首先完成首次上下文切换，再取走入口闭包；进入可能永不返回的闭包前释放临时核心引用。普通恢复沿原调度栈完成尾部。操作系统的切入/切出钩子继续在交接临界区维护 CPU 当前身份；退出与析构钩子在任务上下文执行，三个阶段不能合并成同一个钩子。

### 3.2 回收事务与读者保护

回收事务要求线程已经退出且不在 CPU 上，没有迁移、期限预留或通知、在途回调、收件箱投递及睡眠定时器。它从登记记录中唯一取出执行资源，清除调度状态中的上下文与地址空间句柄，并临时持有强管理租约，防止并发连接先释放操作系统扩展。任务上下文回收器在锁外依次释放架构上下文、TLS 和栈，把 MM 令牌交给独立回收协议；完成后以释放语义发布“执行资源已回收”。

这个租约只覆盖一次资源释放事务。普通句柄和扩展借用保留的是任务对象与操作系统状态，不能通过它们访问已释放的执行上下文或栈。当前调用链没有远端栈读取接口，因此不引入没有消费者的栈引用类型；将来增加栈观察者时必须先加入独立栈保护，不能用管理句柄代替。

最终对象回收继续经过登记表锁、外部租约、代次检查、调度活动关闭和回调认领协议。CPU 当前对象的裸指针借用由中断/抢占钉住与在 CPU 所有权保护，收件箱裸指针由投递租约保护；这里的等价性依赖这些读者逐一退出，并非仅凭共享引用计数推断 RCU 宽限期已经结束。敏感上下文丢弃最后一个管理引用只发布回收工作，不直接调用可能取得睡眠锁的操作系统析构。

取消队列的强引用保护节点所在的执行对象；收件箱的纪元宽限完成后才拆下节点并把引用交给消费者。“新建”登记记录和唯一创建令牌阻止提前回收。直接回收和任务工作消费者在取得任何锁之前校验上下文，拒绝硬中断、中断/抢占保护、未结束的调度交接及 RT 临界区，防止睡眠析构绕过普通连接的上下文检查。

### 3.3 地址空间交接

切换计划把两个架构上下文和各自的逻辑地址空间作为一次不可重放的交接提交：根据逻辑地址空间身份、CPU 的 active-MM 租约和架构要求准备，架构寄存器切换前执行无失败的提交。

| 转换 | 地址空间所有者与动作 | 回收边界 |
| --- | --- | --- |
| 用户 → 用户 | 切到下一任务的地址空间；共享 CPU 状态身份可走同地址空间分支 | 旧 active-MM 租约随实际硬件切换转交 |
| 用户 → 内核 | 内核线程没有自己的用户地址空间，进入惰性内核态 | 内核任务对象的地址空间令牌与 CPU 借用的 active-MM 分开 |
| 内核 → 用户 | 安装下一任务的地址空间；AArch64 恢复被惰性路径替换的页表基址 | 仅在不再有 CPU 激活租约时释放旧地址空间 |
| 内核 → 内核 | 继续 CPU 的惰性地址空间状态 | 不因释放一个内核线程的栈而释放 CPU 仍借用的地址空间 |

同地址空间快路径不代替独立的内存屏障注册、跨处理器同步和用户返回检查。用户执行上下文的创建和 exec 后刷新继续验证调度选择的地址空间、硬件根和 CPU 足迹；硬件返回边界保留原有的 TLB 与同步要求。普通 QEMU clone/exec 的通过只能证明运行路径，不能替代针对弱内存排序的独立屏障测试。

四类实际切换在同 CPU、同优先级 FIFO 的两个带地址空间上下文和两个内核上下文中验收：使用始终有效的内核页表根且不进入用户态，运行时地址空间身份和 CPU 租约是真实对象；首次入口、阻塞恢复和让出后检查中断已恢复、阻塞许可有效。active-MM 的独立寿命单独验证：第一个地址空间在被第二个替换后释放；最后一个用户线程退出并连接后，其地址空间仍被内核惰性状态借用，切换到另一地址空间后才释放一次；不用管理句柄引用数代替 CPU 租约退出证明。

用户返回屏障以真实用户态测试维护：两个线程绑定不同 CPU，注册并调用私有加速内存屏障，远端只使用编译器屏障，轮次间隔睡眠并经过实际用户返回，双侧同时读到旧值即为失败。内核侧证明与运行证据分别维护：调度中的屏障状态在内核线程上保留借用地址空间的身份；目标收集在 CPU 发布租约和 raw 运行队列锁保护下选择同地址空间的 CPU，因此同地址空间的“用户→内核→用户”不采用 Linux 空 mm 分支的跳过 IPI 路径；扫描前与最后同步应答后执行全序栅栏，硬 IPI 回调执行全屏障，运行队列身份改变也有全序栅栏。同地址空间快路径不能绕过上述同步。四架构 QEMU 验证真实系统调用、用户执行和返回路径，但不穷尽硬件弱内存交错，也不能把 litmus 通过当成形式化证明。

## 4. 等待、唤醒与 RT 锁

RT 锁语义通过公开运行时接口的确定性交错测试约束：持有期间的高优先级抢占、内层阻塞期间的外层超时、读者排空、同 CPU 本地锁竞争、嵌套迁移守卫与远端亲和性更新，以及信号量的 FIFO 许可、超时和取消。外层超时测试先用高优先级任务抢占持有者以明确结束其自旋，再触发内层停车；失败时用普通唤醒取回测试控制权，并检查实际停车处理结果，不依赖 QEMU 超时判定。

### 4.1 唤醒批次与计数

唤醒队列节点是每任务的，不是每等待代次的：等待者看到唤醒标记后，可以在旧批次发送前结束这一代并开始下一代，同一任务句柄进入两个尚未发送的批次是合法合并，不能把合并当错误断言。唤醒批次分别保存选中的等待记录数和去重后的任务队列：只有成功标记“已唤醒”才计入选中数；唤醒限额、唤醒-唤醒两次选择、重排中的唤醒部分及返回值都使用选中数，任务队列只负责去重与调度通知，这与 Linux 先发布出队状态、对已排队任务合并通知、返回计数按选中等待记录的顺序一致。

批次入队在比较交换前执行完整屏障，失败合并路径也发布先前状态；发送端在释放节点之后、调用调度唤醒之前执行匹配的完整屏障。节点链接、共享引用和外部租约的所有权转移保持单次取得和释放。

### 4.2 PI 与优先级通知

对队列中的拥有者完成优先级继承重排后，只有严格高于当前任务的 RT 拥有者才请求立即抢占，相同优先级保持 FIFO 顺序；运行队列事务分别携带抢占决定和维护工作，不需要抢占时，定时器及平衡维护仍能交给拥有者 CPU，不用抢占位代替工作通知。公平类沿用完整运行队列的既有判断；已存在立即抢占时不重复取消当前请求保护。当前正在运行的拥有者的优先级更新分支仍保留旧的立即重调度，需继续按运行中 RT/期限类的类钩子、配额和定时器生命周期核验。

### 4.3 同键重排

普通 FUTEX_REQUEUE 与 FUTEX_CMP_REQUEUE 允许源、目标键相同，仍逐项计入选中的等待者；只有 PI 重排拒绝相同键。同键时保留原位遍历并按重排限额更新等待记录，不提前返回已唤醒数，也不改变入队、唤醒或桶锁顺序。唤醒计数按选中记录数而非去重后的任务数，与第 4.1 节一致。

## 5. 信号与线程组退出

Linux 对默认、非 coredump 且不受跟踪延迟的致命信号，先提交线程组退出决定和原始退出码，再向所有线程发布 SIGKILL 并唤醒；线程取信号时优先处理该退出决定，组退出保留已提交的退出码。因此 vfork 父线程不仅能被 SIGKILL 终止，也应能在孩子完成前被默认 SIGTERM 或实时信号终止——只排队原始信号、让可终止等待看不到致命信号是错误实现。

### 5.1 组退出决定与共同门禁

线程组退出决定是不可撤销的一次性决定，由进程和信号管理器共享；“最后退出码”只记录尚未形成组决定时的线程退出值。处置、待定与组退出的短状态锁不执行调度通知；入队与发布在释放共同门禁后释放停止状态并显式唤醒任务。共同任务上下文 PI 门禁从安全状态扩展为信号、退出和 clone 最终发布共享的串行边界：clone 在该门禁下检查父线程致命信号，依照 Linux 在 PID 发布前返回 EINTR；组退出在同一处置锁内提交共享退出状态和所有其他线程的 SIGKILL，释放门禁后才通知，且先于每线程的一次性退出声明，返回最先提交的等待状态。“先提交状态、解锁后逐线程发送”的旧窗口被删除。

发布前取得处置锁后重新核验保留的线程集合；新接收者登记和 exec 的线程号更名使用同一处置锁，防止锁外快照漏掉新成员。已经作出的退出决定会为后来准备的接收者设置 SIGKILL，clone 的最终发布检查仍会拒绝它。每线程的一次性退出声明只保留一份，退出开始时委托声明而不是维护第二个标志；发送资格排除已开始退出的线程，退出期间的信号检查不再重入清理。被屏蔽、带用户处理器、coredump 或由操作系统要求延迟致命处理的信号不走提前组终止分支；实时信号按 Linux 的忽略/停止掩码默认终止，不落入默认忽略分支。

### 5.2 信号队列的准备与发布

信号队列的准备和发布分开：准备对象在进入处置锁前持有标准信号的堆盒子或实时信号的单个链表节点，锁内只插入或拼接，重复或未使用的预备对象在解锁后释放。实时 FIFO 用已分配节点传递，避免在处置锁内扩容。排队信号的多余参数按 Linux ABI 忽略而不报 EINVAL；实时信号保留每个排队实例。

线程定向通知通过调度身份（线程标识到句柄再到用户任务引用）保留原调度代次，不重新查询可能复用的数字线程号；组通知在解析成员后额外复核进程身份，避免成员快照过期后唤醒无关进程。不新增弱引用登记表；强制线程号复用交错的直接证据仍缺。

### 5.3 登记的最终释放

线程信号管理器在最后一个强引用析构时主动注销其进程登记，不依赖一次无关的未来信号扫描才清理失效弱引用。登记匹配使用被引用保护的对象地址而不是线程号：线程号可能因 exec 改变，析构时的匹配不能以最初的数字为准，否则会误删复用同一线程号的新对象，或使更名后的旧登记无法匹配。地址只比较、不解引用；正在析构的对象由自身共享字段保持有效，隐含弱引用持续到析构完成，取走登记不会提前释放它。注销在原登记锁内移出弱引用、锁外丢弃；同一登记被后续扫描再次清理是无副作用的。进程准备的可失败分配（组退出状态与进程对象）在发布前传播错误，引导和测试入口明确处理初始化失败。

### 5.4 vfork 等待

vfork 的完成等待必须响应真实致命信号：SIGKILL 要能在孩子仍未释放地址空间时结束父线程的等待并断开孩子的完成指针，只有正常完成才报告对应的跟踪事件。完成状态属于线程生命周期而不是进程等待状态；clone 在发布前做可失败分配，父线程持有激活后的用户任务引用等待指定孩子；退出对每个线程通知，exec 通知其当前线程。父线程被杀死时，在该孩子的中断锁内取走完成对象、解锁后释放；普通信号则继续等待。

传统 clone 不沿用 clone3 的线程退出信号限制，也不拒绝 Linux 支持的“线程组 + vfork”组合；clone3 自己的参数检查保留。验证“线程组 + vfork”这类 libc 包装会在进入内核前拒绝的组合时，必须使用原始 clone ABI，其无效参数返回可能只是测试准备失败而不是内核缺陷。已知缺口：Linux 在退出地址空间阶段即通知 vfork 完成，早于共享内存与文件清理；本项目通知仍在现有退出清理尾部，exec 也在清理尾部通知，阶段对齐待完成。

## 6. exec 与清理边界

exec 的去线程化、地址空间替换、退出资源释放、僵尸发布和父进程等待由操作系统的进程/线程所有者完成；公共等待句柄不替代 wait 系统调用，也不把物理栈释放当作僵尸可见性的条件。非主线程 exec 保持进程 PID 并成为主线程。

### 6.1 清理顺序

exit 与 exec 共用 robust 列表释放路径：在旧地址空间仍可访问时执行既有遍历，再清空登记。exec 的非主线程身份转交发生在该清理之前，遵循 Linux“开始新映像 → 去线程化 → 映像地址空间切换 → 地址空间释放通知 → futex exec 释放”的顺序；Linux 在 robust 拥有者比较前已经交换线程号，所以仍写着旧非主线程号的锁字不应被本线程清理。

### 6.2 robust 锁字的原子更新

robust 拥有者标记必须使用比较替换协议：先读取拥有者，比较失配后重新读取并检查，只有成功替换才按该次锁字决定是否唤醒。读后直接写回会覆盖用户态并发发布的等待位，也不发出所需唤醒。读缺页、写缺页与独占加载/条件存储的重试耗尽分别作为独立错误返回：任务上下文解决相应访问权限的缺页，只有重试耗尽才让出 CPU；不能把只读访问错误一律当作写缺页。

用户内存比较替换原语按架构提供统一契约（返回观察值）：x86_64 用锁定 cmpxchg；AArch64 用独占加载/存储并在成功后加内存屏障；RISC-V 用带获取释放语义的 LR/SC，按位数区分 RV32/RV64 并保持与加载一致的符号扩展；LoongArch 用 LL/SC 配合屏障。独占访问沿用有界重试错误，架构异常表同时覆盖读与条件存储。普通 Rust 引用不指向用户锁字；缺页解析与地址空间锁不进入原子指令区间。

## 7. 共享内存附接生命周期（设计中）

本节描述尚未实现的目标设计与已确认的差距，现有实现仍按 PID 清理附接并保留已知的正确性缺口。SysV 共享内存的段与管理者已迁入 IPC 域：系统调用层只保留命令解码、用户输入输出和事务编排，任务操作直接调用域清理，不反向依赖系统调用导出；段创建参数由参数对象承载，统计与按索引查找通过登记表方法完成。

### 7.1 Linux 语义与本项目差距

Linux 的附接计数随 VMA 建立与关闭维护：映射的存活绑定于所在地址空间的 VMA，不绑定于创建映射的 PID；带关闭操作的 VMA 禁止通过合并移除；shmdt 通过当前地址空间的 VMA 来源和原附接地址分离映射。宿主 Linux 的实测计数为：初次附接 1，权限分裂后 3，恢复权限仍 3，取消中间页后 2，fork 孩子存活时 4，孩子退出后 2。中段取消映射会先执行两次 VMA 分裂并调用新片段的建立回调，移除中间 VMA 才调用关闭回调——最终数量从 1 变为 2，实际发生两次建立与一次关闭；生命周期回调不能只按最终根或附接净增量生成。

当前差距有三点：其一，退出按 PID 主动清理附接，会移除仍由共享地址空间使用的映射；其二，shmdt 按调用者 PID 查找，无法分离另一共享地址空间进程建立的映射；其三，旧测试要求共享地址空间下孩子退出后计数为 1，在 Linux 上不成立（等待前后均为 2），该预期已撤回，需以正确的共享映射存续与分离行为替代，而不是只改断言。

### 7.2 目标设计

逻辑附接跟随已提交的 VMA 身份，复用现有 VMA 事务；物理页仍由共享内存对象、映射操作与槽位持有；不增加通用插件或第二个内存对象登记体系。实现必须记录操作级的分裂、建立和关闭阶段，分别处理“已发布分裂”“未发布失败”和“已发布待 TLB 确认”三类结局；map/unmap/mprotect/mremap/fork/clear 并不统一经过同一条元数据后继路径，未经过普通回执的未发布地址空间清理也不能遗漏。

锁顺序同时迁移：映射准备先取得稳定的段与物理对象预留，释放 IPC 与段锁后再进入地址空间事务；IPC_RMID 竞争由该预留保护，失败撤销预留，不在地址空间锁内重走原有链。正式记录在映射事务发布后维护，随后释放地址空间锁，最后释放临时引用。准入引用保证：即使另一操作执行 IPC_RMID，已准入的附接仍保留登记，取消且无其他附接时才删除；普通观察者的共享引用只保留对象内存，不保持 IPC 登记。已发布待 TLB 确认的映射保留正式附接，不因返回错误而误删。

地址空间的用户所有权结束时即关闭逻辑附接，不等惰性 active-MM 与旧页表所有者最终析构才更新计数；同时必须串行化仍在进行的 VMA 修改，并禁止已关闭映射重新发布附接。现有进程拥有者计数与运行时每任务钉住都不能单独当作 Linux 的 mm_users，具体退出准入、内核读者、操作 PID 和任务上下文释放协议需一并证明，然后才能把 exit/exec 的 vfork 地址空间释放通知移到正确阶段。验收覆盖共享地址空间、普通 fork、VMA 分裂与不合并、部分取消映射、重映射、exec、IPC_RMID 最后附接、发布前失败和发布待 TLB 确认；保留旧 VMA 元数据快照或 active-MM 时，逻辑计数与物理资源寿命分别验证；所有计数变更和关闭只发生一次，释放路径不在 raw 锁或中断上下文取得可睡眠锁。

## 8. CPU 下线与 idle 边界

CPU 生命周期的状态机与发布排空设计另见[《CPU 下线中的发布排空》](cpu-offline-publication.md)；本节只记录与线程生命周期相关的边界约束。

下线是要求调用方先排空的最终事务：发布者、拥有者工作、空闲拉取、定时器和任务目标全部排空后才允许；完整测试套件启用文件系统与网络后，其固定的服务线程（块层队列、网络执行器）仍持有 CPU 所有权，释放测试线程的激活预留并不撤销这些服务——完整套件的 CPU 排空以实际服务退出为前提，逻辑退出不等于排空条件。本项目的下线不包含 Linux 的完整设备与线程停放编排（先清除活跃掩码并等待宽限、停放每 CPU 管理线程、块层先关准入再等在途请求、RT 钉住检查），不能把受阻的工作线程当作已停放。

下线钩子不可阻塞：在关中断且持有登记表与根域锁时取得全局内核地址空间锁、并可能等待远端 TLB 关闭的调用违反钩子契约，会与持地址空间锁等待目标 CPU 的路径形成锁反转；隔离资源继续由 TLB 隔离区持有，普通地址空间事务通过重试回收。验证时钟事件的线程必须先物理结束：连接句柄只等待逻辑完成，需等待执行资源回收完成后再发下一次下线请求。

idle 入睡前必须在关中断的等待边界重检待处理工作：测试邮箱的请求不是普通可运行任务，仅发物理 IPI 不能形成持久的需要重调度条件，中断边沿可能在服务点之后、最终入睡检查之前被消耗。最终等待事务在入睡边界同时观察邮箱（武装中、延迟发布、就绪均阻止入睡，完成不阻止）；生产者先投递普通拥有者工作、退出发布租约后才发布可消费状态，取消多余的直接物理 IPI；正常生产构建没有测试邮箱。边界请求“已被消费”与“此刻能够成功下线”是两个条件：持有装配预留时，边界请求必须被消费，但下线必须被拒绝且入口不能执行。拒绝的诊断记录只在故障注入构建中存在，在原判断处记录、所有锁释放后输出，不改变原短路判断与取消顺序；同 CPU 的固定停止线程没有热插拔停放契约，不能为测试放宽下线门禁，且拒绝不得释放 idle 的 active-MM。

## 9. 经验与易错点

以下条目从本轮开发过程中沉淀，每条写明原则与它防止的失败模式，供后续调度、锁与兼容性工作复用。

### 9.1 验证纪律

回归必须先在旧实现上确定性失败，再验证修复；修复后的通过不能反推旧问题已被覆盖，也不能用放宽断言、延长超时或增加重试替代修复。目标编译通过不等于运行通过；单次通过、重跑通过或同代码另一入口通过，都不能当作历史间歇性失败已定位或已修复。

兼容性结论不能从共享路径推广：共用创建主体的通过不能推断 clone3、独立 fork 等专用入口已覆盖；单项场景的通过不能推广为每个 flag、每种错误注入和所有体系结构的完整证明。宿主 Linux 上的同用例对照是有效的 ABI 参考，但不是 PREEMPT_RT 构建证据，且宿主进程继承的状态（如 no_new_privs 已置位）可能使某些初态无法构造。本地 Linux 源码树未启用 RT 配置时不能作为 RT 语义或性能证据。性能对照必须交错启动、对多轮取中位数，且两侧除被测改动外完全一致；范围重叠的微基准只能排除数量级退化，不能保证实时上界。

### 9.2 并发与锁

不能用共享引用计数或临界区计数推断 RCU 宽限期结束；每个被借用对象都要有独立的读者退出证明。锁内不做可失败分配或扩容：可失败的工作一律移到锁外准备、锁内提交。失败路径要先释放持锁线程并收回复，避免留下关中断自旋的 CPU。调度通知在锁外发出；只保护短状态的锁不承担唤醒责任。

唤醒合并是合法行为：每任务的唤醒节点可以跨等待代次复用，把合法合并当作错误的断言本身就是缺陷；返回计数按选中的等待记录数而不是去重后的任务数。idle 入睡前必须在关中断边界重检待处理工作，不能靠已经消耗的中断边沿证明可睡眠。诊断信息在原判断处记录、全部锁释放后输出，避免为诊断引入新的锁序或原子开销；非测试构建不保留诊断状态。

### 9.3 生命周期与资源

逻辑退出不等于物理切出，也不等于最终引用消失；连接只承诺返回码可见，物理回收要等执行资源回收完成。发布前检查与发布后尽力写不能合并：创建类输出（如 pidfd）的错误在发布前报告并回滚，发布后输出（如 parent_tid）的写失败不撤销已发布的孩子。robust 锁字更新必须比较替换，读后写会覆盖并发发布的等待位。可失败分配要在第一次分配前建立未发布上下文，让任何失败都有明确的撤销路径；描述符先于实体分配，避免描述符失败遗失实体。安装后的析构不得删除已被他人关闭并复用的资源编号——预留、就绪、已安装三态就是为此划分的。

共享内存附接属于 VMA 而非创建者 PID；VMA 分裂时建立/关闭回调次数与净增量不一致，生命周期回调不能按净增量生成。队列局部的完成标识复用是驱动层的合法契约：出现“相同标识”先核验该队列的契约，再考虑归因调度或生命周期错误，不要把驱动语义误判为内核缺陷。

### 9.4 ABI 判定

厂商 ABI 的字段单位必须对照厂商驱动源码核实——毫秒与微秒之差会把超时缩短一千倍，让正常请求被判超时。libc 包装可能在进入内核前拒绝参数组合（如 musl 的 clone 包装拒绝线程组标志），此时测试必须使用原始系统调用 ABI； EINVAL 可能只是测试准备失败而不是内核缺陷。同一机制在不同入口（clone/clone3/fork、execve/execveat、exit/exit_group）各有独立参数校验与错误顺序，结论按入口分别记录。

### 9.5 环境与工具链

共享构建目录会被并行构建写入未来的不兼容报告，污染静态检查门禁；正确做法是用独立构建目录重跑，保持门禁与允许范围不变，而不是删除报告或扩大豁免。增量标准库测试以提交为基线选择软件包，未提交的修改不会被选中，不能把“未选中”当作通过。失去调用方的导入与转发残留会被拒绝警告的构建拦下，接口收敛要连同死代码一起清理。

## 10. 验证状态与开放问题

本节汇总已取得的验证范围与仍未关闭的问题；未执行的矩阵不记为通过，进行中的运行不视为结论。

### 10.1 已验证范围

### 10.3 开放问题

以下问题尚未关闭，后续工作不得把相邻通过记录当作它们的修复证据：共享内存 VMA 生命周期未实现（共享地址空间红例仍在）；exit/exec 的 vfork 完成通知仍在清理尾部，未对齐 Linux 的地址空间释放阶段；vfork 的跟踪事件（VFORK_DONE）缺少直接观测；同键重排在底层返回“不可用”时的交付路径未结合运行时准入证明；运行中任务的 PI 更新分支仍保留旧的立即重调度；LoongArch 下线非预期拒绝的根因未定位（诊断边界已就绪）；实体板卡上间歇性的硬件与网络冒烟停滞、Axvisor 暂停超时等历史失败均未归因，单次重跑通过不关闭问题；调度与 unsafe 领域的合入前审查仍未完成。

既有验证限制另行记录：RISC-V 的调度器中断窗口压力用例在当前实现与独立历史基线上均失败于“工作线程未全部变为可运行”，属既有问题，保留原断言不计为通过；整个宿主测试库因缺失运行时链接符号无法生成测试程序，可运行的是独立编译的生命周期状态用例与纯算法模型（含交错模型），没有为通过而引入假的运行时实现。
