# 团队成员

TGOSKits 由来自高校、科研机构和企业的开发者共同维护。社区成员按参与方式分为三类：指导老师负责研究方向与长期规划，核心团队承担日常维护、审查和技术决策，贡献者通过代码、文档、测试或问题定位参与社区建设。

成员名单依据公开贡献记录整理，提交代码只是参与方式之一，撰写文档、评审改动、定位问题和组织讨论同样计入贡献，长期投入的成员会随参与方向的变化调整所属类别。

## 1. 指导老师

两位老师来自清华大学计算机科学与技术系，在操作系统方向长期从事教学与科研工作，为社区提供研究方向、课题组织与长期规划方面的指导，也参与重要方案的讨论与取舍。

## 4. 团队联系

社区按事项类型划分了不同渠道，问题反馈、改动讨论和安全报告分别有各自的入口，走对应渠道可以让处理过程更容易被跟踪，也避免信息散落在多个地方。

### 4.1 沟通渠道

社区按事项类型使用不同的渠道，议题用于可跟踪的问题与建议，拉取请求用于具体改动，安全报告则不走公开渠道，以便在修复完成前控制影响范围。

| 事项 | 联系方式 | 说明 |
|------|----------|------|
| 问题反馈与功能建议 | [GitHub Issues](https://github.com/rcore-os/tgoskits/issues) | 使用中遇到的缺陷与改进建议 |
| 代码与文档改动 | [拉取请求](https://github.com/rcore-os/tgoskits/pulls) | 提交改动并讨论实现方案 |
| 安全报告 | GitHub 私有安全报告 | 需要非公开处理的问题 |

需要联系特定方向的负责人时，可以在议题或拉取请求中说明涉及的子系统，维护者会转交给相应的成员。安全相关问题请勿在公开渠道披露，也不要先在公开讨论中描述细节。

### 4.2 加入方式

社区欢迎新成员参与，建议先从跑通一次构建与运行开始，再选择与自己关注方向一致的部分入手，这样在提问和讨论时更容易判断问题的边界。

1. 查看[贡献指南](/community/contributing)了解分支、提交信息与验证流程
2. 按[快速开始](/docs/quickstart/overview)在本地完成一次构建与运行
3. 从文档修正、示例补充或缺陷修复入手，提交第一个拉取请求

在某一方向持续投入的贡献者会收到加入核心团队的邀请，参与审查和方向讨论。名单依据实际贡献持续更新，无需单独申请，也没有固定的活跃度门槛。
