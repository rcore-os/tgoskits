# 关于我们

TGOSKits 是一个面向操作系统与虚拟化方向的开源社区，由来自高校、科研机构和企业的开发者共同参与。社区维护统一的代码工作区，将 ArceOS、StarryOS、Axvisor 和共享组件组织在一起，支持跨系统开发、集成验证与工程实践。

## 1. 社区目标

社区通过共享组件、统一工具和公开协作，降低系统软件学习与开发的门槛，让不同方向的工作能够在同一份代码上验证和积累。

### 1.1 统一开发环境

ArceOS 提供组件化内核，StarryOS 提供 Linux 兼容的运行环境，Axvisor 面向虚拟机监控器场景。工作区统一构建、运行与测试入口，参与者可以先跑通自己关注的系统，再逐步了解其他系统和共用组件。

### 1.2 复用共同能力

内存管理、任务调度、设备驱动等能力由多个系统共享。社区根据实际调用关系提取共同机制，减少重复维护和行为差异；缺少共同使用需求的实现则保留在所属系统中，避免只为拆包而增加维护负担。

## 2. 协作原则

社区以公开仓库保存技术讨论、实现和验证记录。成员分工及认可机制见[团队成员](/community/team)，任务安排和交付要求见[贡献指南](/community/contributing)。

### 2.1 公开与可追溯

涉及方向和方案的决定应留下理由、考虑过的选择及最终结论。会议或即时交流产生的结论需要回到相关 Issue 或 PR 中记录，让未参与讨论的人也能理解任务如何形成、实现如何验收。

### 2.2 尊重与分享

讨论聚焦代码、设计和可复现的行为，保持友好，尊重不同经验与背景的参与者。社区鼓励把实践经验整理为文档、示例和技术分享，让后来者能够复用已有结论；检查与审查的具体要求由贡献指南统一维护。

## 3. 相关项目

TGOSKits 将多个独立项目整合到工作区，支持跨系统联调和集中验证。组件来源及与上游之间的同步方式由[仓库管理指南](/docs/contributing/repo)说明。

| 项目 | 定位 |
| --- | --- |
| [TGOSKits](https://github.com/rcore-os/tgoskits) | 社区维护的统一工作区 |
| [ArceOS](https://github.com/arceos-org/arceos) | 组件化内核 |
| [StarryOS](https://github.com/Starry-OS/StarryOS) | Linux 兼容操作系统 |
| [Axvisor](https://github.com/arceos-hypervisor/axvisor) | 基于 ArceOS 的虚拟机监控器 |

[rcore-os 组织](https://github.com/rcore-os)还维护操作系统、虚拟化和教学方向的相关仓库。版本发布与阶段性总结见[博客](/blog)；合作或定制需求的联系入口见[获取帮助](/community/support#32-合作与定制)。

## 4. 入门与参与

初次接触项目时，先运行目标系统，再结合运行结果阅读实现。文档按使用、设计和问题定位划分主题，具体命令和技术细节以主文档对应章节为准。

### 4.1 文档入口

根据当前目标选择对应章节，可以避免在社区说明和技术文档之间反复查找。

| 文档 | 覆盖范围 |

| [快速开始](/docs/quickstart/overview) | 环境准备、构建和首次运行 |

### 4.2 参与路径

各系统的快速开始可以独立阅读。完成一次构建与运行后，再根据关注方向了解代码组织和任务安排。

1. 按快速开始指南运行目标系统，确认环境与基本流程可用。
2. 阅读仓库管理指南和对应架构文档，定位感兴趣的组件或系统。
3. 按[贡献指南](/community/contributing)选择已经纳入当季计划的 Issue，再开始实现和提交 PR。

问题反馈、方案交流和支持渠道见[获取帮助](/community/support)。分享工具、教程和示例时，按[资源贡献要求](/community/contributing#55-资源贡献)准备材料并确认任务安排。
