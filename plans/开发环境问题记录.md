## 问题记录

### 001. StarryOS 构建缺少 aarch64-linux-musl-cc

| 项目 | 内容 |
|---|---|
| 日期 | 2026-07-07 |
| 标签 | `starryos` `musl` `交叉编译` `lwprintf-rs` `环境` |
| 触发命令 | `cargo xtask starry qemu --arch aarch64`（构建阶段同样会失败） |
| 状态 | **已解决** |

#### 现象

构建 StarryOS 时，在编译 `lwprintf-rs` 阶段失败：

```
warning: lwprintf-rs@0.3.3: Compiler family detection failed due to error:
  ToolNotFound: failed to find tool "aarch64-linux-musl-cc": No such file or directory (os error 2)

error: failed to run custom build command for `lwprintf-rs v0.3.3`
...
error occurred in cc-rs: failed to find tool "aarch64-linux-musl-cc": No such file or directory (os error 2)

Error: failed with status: exit status: 101
```

构建日志中可见 axbuild 为 musl 目标注入了交叉编译环境变量：

```
CC_aarch64_unknown_linux_musl=aarch64-linux-musl-cc
AR_aarch64_unknown_linux_musl=aarch64-linux-musl-ar
CFLAGS_aarch64_unknown_linux_musl=-mgeneral-regs-only
```

使用的 QEMU 配置：`os/StarryOS/configs/qemu/qemu-aarch64.toml`。

#### 环境

- OS：Linux（本地非容器环境）
- 项目：`tgoskits` 工作区
- Rust：nightly（与仓库 pinned 工具链一致）
- 是否使用容器：**否**（容器镜像内已预装 musl 工具链，本地裸机构建需自行安装）

#### 排查过程

1. 从终端日志定位失败 crate：`lwprintf-rs` 的 `build.rs` 通过 `cc-rs` 编译 C 源码。
2. 确认 axbuild 期望的编译器名为 `aarch64-linux-musl-cc`（见 `scripts/axbuild/src/context/arch.rs` 中 `gnu_tool_prefix: "aarch64-linux-musl"`）。
3. 在 shell 中检查工具是否存在：
   ```bash
   which aarch64-linux-musl-cc aarch64-linux-musl-gcc
   echo "$PATH" | tr ':' '\n' | grep -i musl
   ```
   结果：均未找到，PATH 中无 musl 交叉编译器路径。
4. 对照仓库文档：
   - `README_CN.md` §3.1 推荐容器镜像（已含工具链）
   - `os/arceos/README.md` 给出 musl.cc 工具链下载方式
   - `docs/docs/build/test/assets.md` 说明 StarryOS/测试资产构建依赖 `{arch}-linux-musl-gcc`

#### 根因

StarryOS 的 std 用户态构建目标为 `aarch64-unknown-linux-musl`，依赖 **musl.cc 提供的交叉编译工具链**（`aarch64-linux-musl-cc` 等）。本地环境未安装或未加入 `PATH`，导致 `cc-rs` 找不到编译器。

这与内核目标 `aarch64-unknown-none-softfloat` 不同：后者走 Rust 交叉编译，而 musl 用户态组件（如 `lwprintf-rs`）仍需 C 交叉编译器。

#### 解决方案

**方案 A：本地安装 musl 交叉工具链（已采用）**

安装目录：`~/tools/`。一次性安装仓库常用四套工具链：

```bash
mkdir -p ~/tools && cd ~/tools

# aarch64 / riscv64 / x86_64 来自 musl.cc
wget https://musl.cc/aarch64-linux-musl-cross.tgz
wget https://musl.cc/riscv64-linux-musl-cross.tgz
wget https://musl.cc/x86_64-linux-musl-cross.tgz
tar zxf aarch64-linux-musl-cross.tgz
tar zxf riscv64-linux-musl-cross.tgz
tar zxf x86_64-linux-musl-cross.tgz

# loongarch64 来自 LoongsonLab 发布
wget https://github.com/LoongsonLab/oscomp-toolchains-for-oskernel/releases/download/loongarch64-linux-musl-cross-gcc-13.2.0/loongarch64-linux-musl-cross.tgz
tar zxf loongarch64-linux-musl-cross.tgz

# 当前终端生效
export PATH="$HOME/tools/x86_64-linux-musl-cross/bin:$HOME/tools/aarch64-linux-musl-cross/bin:$HOME/tools/riscv64-linux-musl-cross/bin:$HOME/tools/loongarch64-linux-musl-cross/bin:$PATH"
```

持久化写入 `~/.bashrc`：

```bash
# tgoskits musl cross toolchains
export PATH="$HOME/tools/x86_64-linux-musl-cross/bin:$HOME/tools/aarch64-linux-musl-cross/bin:$HOME/tools/riscv64-linux-musl-cross/bin:$HOME/tools/loongarch64-linux-musl-cross/bin:$PATH"
```

**方案 B：使用项目容器（免本地安装）**

```bash
docker pull ghcr.io/rcore-os/tgoskits-container:latest
docker run -it --rm \
  -v "$(pwd)":/workspace \
  -w /workspace \
  ghcr.io/rcore-os/tgoskits-container:latest
```

容器 Dockerfile 参考：`container/Dockerfile`（工具链安装在 `/opt/*-linux-musl-cross/bin`）。

**方案 C：macOS Apple Silicon**

可参考 `apps/starry/macos-selfbuild/prepare_host_tools.sh`，通过 Zig 包装器或 Homebrew 提供 `aarch64-linux-musl-{cc,gcc,ar}`。

#### 验证

```bash
# 1. 确认编译器可用
aarch64-linux-musl-cc --version
# 预期：aarch64-linux-musl-cc (GCC) 11.2.1 ...

# 2. 重新构建
cd /path/to/tgoskits
cargo xtask starry build --arch aarch64
# 预期：lwprintf-rs 编译通过，最终输出 starryos / starryos.bin

# 3. 完整运行（需已准备 rootfs）
cargo xtask starry rootfs --arch aarch64   # 首次
cargo xtask starry qemu --arch aarch64
```

本次验证结果（2026-07-07）：

- 四套 musl 工具链安装成功
- `cargo xtask starry build --arch aarch64` 构建成功
- 产物：`target/aarch64-unknown-linux-musl/release/starryos`

**快速自检命令**（以后遇到类似 `ToolNotFound: *-linux-musl-cc` 可优先执行）：

```bash
for cc in aarch64-linux-musl-cc riscv64-linux-musl-cc x86_64-linux-musl-cc loongarch64-linux-musl-cc; do
  printf '%s: ' "$cc"
  command -v "$cc" || echo 'NOT FOUND'
done
```

**同类问题预判**：构建 ArceOS/Starry 应用、运行 `cargo xtask test` 中涉及 musl 用户态 prebuild 的流程，均可能因缺少对应架构的 `*-linux-musl-cc` 失败；按目标架构补装对应工具链即可。
