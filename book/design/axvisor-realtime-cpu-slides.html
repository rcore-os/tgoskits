核心思想

用物理 CPU 所有权分区来做实时，
而不是把实时任务建模成普通调度器里的“高优先级线程”。

❌ 传统做法：高优先级线程

  • 仍在普通 run queue 里，受 tick、迁移、锁竞争影响
  • 与 guest vCPU / host 线程共享一个核，抖动不可控
  • 实时性依赖“调度器足够聪明”

✅ 本设计：独占物理核

  • pCPU3 完成最小初始化后跳出普通调度器
  • 不进 run queue、不被迁移、不收普通 timer tick
  • 运行 ax-rt 独立协作式执行器，host 只能只读观测

第一版成功标准：“CPU 所有权不会混淆” —— host 只调度 host 核，RT 核只跑实时任务。

设计目标与当前非目标

第一版有意收敛边界，把“隔离”做扎实，再谈能力扩展

✔ 目标

  • 提供可观察、可扩展的单核实时执行域
  • 与普通 host scheduler / sleep / IPI / block runtime 完全隔离
  • 构建期 opt-in：不设 AX_RT_CPU 时行为与原版零差异
  • 执行器抽成独立 crate，可被多内核复用

✘ 当前非目标（实现边界，非架构终点）

  • 只支持保留最后一个逻辑 CPU（如 4 核的 AX_RT_CPU=3）
  • 暂无 RT 专属 timer IRQ：sleep 由执行器轮询 deadline 唤醒
  • 任务为启动时静态注册的 fn()->!，不支持动态创建
  • 暂不支持跨核迁移 / RTOS guest 独占核 / RT 设备直通

💡 关键取舍：把“最后一个 CPU 是 RT CPU”的判断收敛为唯一事实（在 axruntime 里）， 绝不在 VM / IRQ / scheduler / shell 里各判一遍 —— 这是后续所有扩展的前提。

机制在 ArceOS，能力在 ax-rt，集成层只需“填三样东西”

ArceOS 提供的钩子（内核无关）

// axruntime/src/lib.rs —— 被 secondary 分流调用
pub(crate) fn run_realtime_secondary(cpu_id: usize) -> ! {
    unsafe extern "Rust" {
        safe fn ax_realtime_secondary_main(cpu_id: usize) -> !;
    }
    ax_realtime_secondary_main(cpu_id) // ← 集成层实现
}

谁提供这个符号，谁就拿到那个 RT 核。

集成层要填的三样东西

① RT 入口符号
#[no_mangle] ax_realtime_secondary_main
② 静态任务表
&'static [RtTask]（≤ 8 个）
③ 单调时间源
fn() -> u64

components/ax-rt 内部结构

#![no_std]，与 ax-task 平级，复用底层 CPU context 而非 host run queue

① 任务模型 task.rs

  • RtTask::with_priority(name, period, prio, run)
  • 执行器 round-robin 扫描 + 按有效优先级择优
  • 无抢占：任务须主动调 rt_yield_now / rt_sleep / rt_delay_until / rt_exit

② 上下文隔离 context.rs

  • 每任务独立 64KB 栈 + axcpu::TaskContext + RT 私有 thread header
  • 用 CPU-local current-thread switch 事务切换
  • 不碰 ax-task 的 run queue / CurrentTask / wait queue / timer wheel

③ 同步原语 sync.rs

  • RtMutex：协作式可睡眠锁，拿不到 → 标 Blocked 并 yield
  • 支持递归加锁（recursion_depth）
  • 支持优先级继承（donate / restore）+ 按优先级唤醒 waiter

④ 输出通道 output.rs

  • RT 侧不写 host UART、不拿 console lock
  • 1024B 定容环形缓冲：RT 写 rt_output_write，host 拉 rt_read_output
  • 临时但安全的观测面

优先级调度

  • 就绪任务中选 effective_priority 最大者运行
  • 值越大越先跑（demo：prio-high=40 > prio-mid=30 > prio-low=20）

优先级继承（防优先级反转）

  • 高优先级 waiter 阻塞在锁上 → 把自身优先级 捐给持锁者
  • 持锁者 unlock 时 恢复 base_priority，并唤醒最高优先级 waiter
  • 自验证 prio-* 任务：确认中优先级任务不会插队抢在被抬升的持锁者之前

递归锁

  • 同一任务重入 → recursion_depth += 1；unlock 逐层递减
  • 自验证 recur-* 任务：确认内层 drop 不释放锁，waiter 只在外层 unlock 后进入

现状小结

当前是一个 isolated cooperative realtime executor
隔离做扎实了，但“实时”还停留在协作式 + 轮询唤醒

时间/唤醒

sleep 靠执行器 loop 扫描 deadline，无 RT 专属 timer IRQ

通信 ✓

双向 bounded mailbox + GIC SGI doorbell 已打通：host↔RT 互发 IPI（SGI 1 / SGI 2）

设备/中断

无 RT-owned IRQ / 设备直通，无设备所有权与 probe 排除规则

→ 下一步的主线，正是把“协作式轮询”演进为真正的中断驱动实时。

🎯 将来计划：中断（IRQ）接入

主线目标：把 busy-polling sleep 换成 RT 专属 timer IRQ，并打通 RT-owned 设备中断

阶段一 · RT 专属 Timer IRQ

  • 为 RT 核单独申请 timer IRQ line，不并入 host CpuMask
  • 执行器从“轮询 deadline”改为 timer 中断唤醒 Delayed 任务
  • 降低唤醒延迟与 CPU 空转，得到确定性的时间基准

阶段二 · IRQ-safe 同步原语

  • 设计可在中断上下文安全使用的原语（当前 RtMutex 仅限任务间协作）
  • 明确 IRQ 上下文下的优先级语义与临界区边界

✓ 阶段三 · host ↔ RT bounded mailbox（已落地）

  • 定容双向 mailbox 表达 host↔RT 通信（替代只读观测）
  • GIC SGI doorbell 双向通知：host→RT 走 SGI 1、RT→host 走 SGI 2，QEMU 验证 rt_notifications=1, host_notifications=1

阶段四 · RT-owned 设备中断直通

  • 接入前先补齐设备所有权配置 + probe 排除规则
  • RT 核独占某设备的 IRQ，事件直达 RT 任务
  • 把 IRQ → RT 任务唤醒建成显式事件/队列契约
